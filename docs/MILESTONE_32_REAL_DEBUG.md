# 里程碑 32：真实单步与断点

## 目标

把 `debug FILE` 从镜像查看器升级为调试真实 Ring 3 进程的 monitor。
调试目标不再在每次 `g` 时复制为临时文件并从头执行，而是作为调度器
中的 STOPPED 任务保留完整地址空间、内核栈和异常现场。

## 调试目标生命周期

1. `proc_spawn_file_paused()` 装入 flat 或 ELF32 镜像。
2. 初始 52 字节 Ring 3 帧构造完成后，任务直接进入 `TASK_STOPPED`。
3. Monitor 读取 `task->esp` 指向的初始现场并显示入口寄存器。
4. 执行命令时把任务置为 READY，Monitor 用 `TASK_WAIT_PROC` 睡眠。
5. 目标命中调试事件或退出时，当前任务切回 Monitor。
6. Monitor 退出时杀死并回收暂停目标，释放 VM、fd 与任务槽。

## 单步

`t` 在保存的 EFLAGS 中设置 TF，恢复用户上下文后 CPU 执行一条指令，
随后产生 #DB。异常入口清 TF/RF 并挂起目标，Monitor 展示：

- 8 个通用寄存器、EIP、EFLAGS、CS/SS；
- 目标 CR3 与当前 CR2；
- EIP 开始的 3 条反汇编；
- 用户栈顶 4 个 32 位字。

## 断点

`bp [addr]` 把目标进程中的指令首字节替换为 `0xCC`：

1. Ring 3 执行 INT3，产生 #BP，CPU 保存的 EIP 指向断点后一字节。
2. 调试入口从 EIP-1 找到断点并把原字节写回目标页。
3. 保存 EIP 回退到断点地址，挂起任务并显示命中现场。
4. `g` 使用 TF 隐式执行原指令；下一条 #DB 依次重装断点并继续，
   因此持久断点可以重复命中。

`bl` 列出断点，`bc` 恢复全部原字节并清除断点。

INT3 属于用户可主动执行的软件中断，会检查 IDT 门 DPL。只把异常桩装为
DPL=0 时，Ring 3 的 `0xCC` 会先触发 #GP；因此向量 3 单独开放为 DPL=3。

## step-over

`p` 在当前指令为 `call rel32` 时，在返回地址安装临时断点后续跑。
函数 `ret` 回到返回地址时命中 #BP，Monitor 恢复原指令并停在调用之后。
非 call 指令退化为普通 `t` 单步。

## 命令

```text
r                 真实寄存器、页表与镜像信息
t [addr]          单步
p                 step-over call
g [addr]          从当前断点/暂停点继续
bp [addr]         安装持久 INT3 断点
bl / bc           列出 / 清除断点
d [addr]          内存转储
u [addr]          反汇编
e addr bytes      修改目标镜像与进程内字节
w                 写回原文件（不写入 INT3 补丁）
q                 退出并回收目标
```

## 验证

`tools/test-asm.py` 共 34 项，新增验证：

- 暂停进程和真实入口寄存器；
- TF/#DB 单步后 EIP 与 EAX 变化；
- call 返回地址临时断点与 step-over；
- 持久 INT3 断点命中、地址展示、自动重装和继续；
- 断点目标继续执行并正常输出、退出；
- Monitor 退出时目标进程被回收。

## 当前限制

- `p` 只识别直接 `call rel32`，尚未处理间接 call、中断和异常边界。
- 最多 8 个软件断点；尚无硬件执行断点。
- 尚不支持 `a addr` 交互式汇编和直接修改保存寄存器。
- 反汇编基于加载镜像及 `e` 修改，不是完整带符号反汇编器。
