# 里程碑 24：文件系统 v2

## 目标

里程碑 23 已经让文件、目录和 `/bin` 跨重启保留，但文件系统仍有三个明显限制：

1. 单文件最多 12 个直接块，即 48KB。
2. 后台进程与 Shell 可并发调用文件系统，公开操作没有统一临界区。
3. 只能删除和重新创建路径，没有 `rename` 与统一元数据查询。

本里程碑完成：

- 一级间接块，100KB 文件可正常写入、读取和重启保留。
- 单 CPU 全局文件系统临界区，保证一次公开操作在原子上下文中完成。
- `rename`、`stat` 系统调用。
- 内核 Shell 与用户态 Shell 的 `mv`、`stat`。
- 用户态 `ls -l` 长格式输出。
- 双进程并发创建/写入验证与跨重启专项测试。

## 1. 兼容旧磁盘的间接块布局

原 inode 正好 64 字节，最后有一个未使用的 `reserved` 字段：

```text
type(4) size(4) nlink(4) direct[12](48) reserved(4)
```

本里程碑把它改名为 `indirect`，没有改变 inode 大小或 inode 表布局：

```text
type(4) size(4) nlink(4) direct[12](48) indirect(4)
```

旧磁盘中的字段始终为 0，因此可以直接挂载。第一次写超过 48KB 时，
文件系统才分配一个 4KB 间接块，里面存放 1024 个块号。

```text
logical block 0..11   -> inode.direct[0..11]
logical block 12..    -> indirect[index - 12]
```

文件系统本身只有 256 个 4KB 块，因此实际单文件上界仍由磁盘容量决定；
新布局已经解除 48KB 的结构限制。

所有目录操作也统一通过 `inode_block()` 解析，目录超过 12 个数据块时同样
可以使用间接块。

## 2. 间接块的一致性

实现覆盖了以下生命周期：

- 首次访问间接范围时分配间接块和数据块。
- 写穿同步时同时标记 inode、间接块和数据块。
- 截断或删除文件时释放全部间接引用及间接块本身。
- 挂载检查验证间接块号、重复引用、越界引用和未使用槽位。
- 间接块内的未使用指针必须为 0，避免隐藏的孤儿块。

## 3. 全局文件系统锁

当前内核是单 CPU 协作/抢占式调度。公开文件系统 API 在完整操作期间关闭
中断，形成全局临界区：

```text
fs_lock()
  resolve path
  allocate bitmap/inode/data blocks
  update directory and metadata
  fs_sync()
fs_unlock()
```

这阻止定时器在超级块、位图、inode 或目录更新到一半时切换到另一个文件
系统调用。嵌套调用通过保存进入前的 IF 状态自然保持锁定，例如
`fs_write()` → `fs_write_at()` → `fs_sync()`。

当前实现优先保证正确性，因此一次大文件写穿期间会暂时关闭 IRQ。后续可以
改成会睡眠的 mutex，并缩小每次 I/O 的临界区。

## 4. rename

`fs_rename(old, new)` 支持：

- 同一目录内改名。
- 文件和目录跨目录移动。
- 移动目录时更新其 `..` 目录项。
- 调整源/目标父目录的 `nlink`。
- 拒绝把目录移动到自身或其子树。
- 拒绝 `"."`、`".."`、不存在的源和已存在的目标。

命名空间修改在一次全局临界区中完成，其他进程不会观察到“两个名字同时
可见”的中间状态。

当前没有实现 POSIX 的“目标已存在时覆盖”语义。目标路径必须不存在，
这样可以把本阶段复杂度集中在跨目录移动和目录关系更新上。

## 5. stat 与 Shell

新增统一元数据：

```c
typedef struct {
    uint32_t inum;
    uint32_t type;
    uint32_t size;
    uint32_t nlink;
} user_stat_t;
```

新增系统调用：

- `SYS_RENAME`：重命名/移动。
- `SYS_STAT`：查询路径元数据。

内核 Shell：

```text
mv /old /new
stat /path
```

用户态 Shell：

```text
mv /old /new
stat /path
ls -l /dir
```

`ls -l` 显示类型、链接数、大小和名字：

```text
d 2 4096 dir/
- 1 102400 big.bin
```

## 6. 自动化验证

新增 `tools/test-fs2.py`，使用独立 `build/test-fs2.img`，共 34 项检查：

- 100KB 文件写入和逐字节读回。
- 两个子进程同时创建并写入各自文件。
- 并发写入完成后逐字节验证。
- `rename` 后旧路径消失、新路径可访问。
- 内核 Shell 的 `mv/stat`。
- 用户态 Shell 的 `mv/stat/ls -l`。
- 文件跨目录移动和目录 `..` 更新。
- 拒绝把目录移动到自身子树。
- 重启后间接块文件、重命名结果和目录均保留。

运行：

```bash
make test-fs2
```

## 7. 当前限制

- `rename` 不覆盖已存在目标。
- 写穿模式下没有日志，断电时仍可能留下部分目录/inode 更新。
- 全局临界区会暂时关闭中断，大文件 I/O 尚未改造成可睡眠 mutex。
- 没有二级间接块；实际文件上限仍受 1MB 文件系统容量约束。
- 没有硬链接、时间戳、权限位和真正的 truncate-at-offset。
- 写穿仍可能导致重复 ATA FLUSH，后续应增加延迟回写与脏块上限。

## 8. 下一步

建议里程碑 25：**延迟回写与崩溃一致性**。

1. 用可睡眠 mutex 替代长临界区中的全局关中断。
2. 增加延迟脏块回写、脏块数量上限和周期性 flush。
3. 为 inode/目录更新设计最小事务或写时复制顺序。
4. 增加断电注入测试，验证挂载时能恢复或明确拒绝损坏磁盘。
