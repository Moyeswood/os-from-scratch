# 里程碑 11a：PCB 调度器 + 键盘环形缓冲（shell 内核线程化）

日期：2026-11-03

## 背景

里程碑 10 之后的最大架构债：**整个 shell（连同游戏/编辑器/cc/用户程序）都跑在 IRQ1 键盘中断处理链里**。键盘处理器直接调用 `shell_handle_char`，于是：

- 8259A 不再投递同优先级的 IRQ1 → 游戏/编辑器只能**轮询 8042**（和处理器抢字节）
- 调度器要靠读 8259A ISR "跳过 IRQ1 在服务中的窗口"，否则抢占会把没 EOI 的中断处理链切走
- `run` 的用户进程执行期间 IRQ0 被跳过，谈不上"多用户进程抢占"

## 新架构

```
IRQ1 处理器 (keyboard.c)            调度器 (task.c)
──────────────────────            ──────────────────
读 8042 → 环形缓冲(256)      ┌→ 任务0 idle  (启动栈, sti;hlt)
→ 唤醒等键盘的任务           │  任务1 shell (内核线程, 阻塞等键)
                            │  任务2~4 演示 A/B/C (start/stop)
消费者:                     └→ 任务5+  (11b: 用户进程)
  shell         kbd_getchar_blocking   ┌ 协作切换: yield/睡眠 (cli+switch_task+sti)
  用户程序      同上 (ESC→27)          └ 抢占切换: IRQ0 (irq0_handler 换帧)
  游戏/编辑器   kbd_pop 原始字节 (自己翻译/跟踪 0xE0/Ctrl)
  cc            kbd_check_esc 非破坏扫描
  splash/testmode kbd_pop/kbd_pop_blocking_press
```

**PCB**：pid/name/state(IDLE/READY/RUNNING/SLEEPING)/esp(44 字节帧)/kstack_top/wait_flags/sleep_until。睡眠靠 `wait_flags` 说明等什么：键盘事件（IRQ1 唤醒）或时间（IRQ0 唤醒）；无 flags 的 SLEEPING = 睡死（demo 任务 stop 状态）。

**关键设计**：
1. **环形缓冲存原始扫描码字节**（按下 <0x80 / 释放 >=0x80 / 0xE0 前缀独立成字节）——游戏要释放码（mario 跟踪按住状态）、编辑器要 0xE0/Ctrl、shell 要翻译后的字符。翻译放在 pop 时做（shift/caps 状态在 `kbd_pop` 里维护），所有消费者字节按序经过，状态不会漂移。
2. **睡眠竞态纪律**：`cli → 重查条件 → 再睡`。否则会漏掉"IRQ1 在查空和入睡之间已把键推入"的窗口（那个 IRQ1 扫描睡眠者时我们还没睡 → 没人叫醒 → 死等下一个按键）。
3. **idle 永远不领状态**：三个切换路径里 `next != &tasks[0]` 才写 RUNNING。否则 idle 被切到后拿到 RUNNING，再被 IRQ0 降成 READY 混进轮转队列。
4. **释放码天然被吞**：处理器独占 8042，释放码根本不进环形缓冲 → 老代码里所有"kbd_drain 空转延时等释放码到达"的舞步（每处 2×2000 万次空转 ≈ 数秒）全部消失，drain 变成清零游标。测试因此整体变快。
5. **type-ahead**：命令执行期间按的键在环形缓冲排队，命令结束后续打进 shell 输入行（老架构直接丢弃）。`user_run` 不再 kbd_drain。
6. **抢占不需要开关**：demo A/B/C 未 start 时是睡死状态，调度器自然看不到它们。`multitasking_enabled` 退化为 A/B/C 的打印门控。
7. **开机顺序**：task_init 必须**先于 sti**（第一个 IRQ0 就走 task_timer_tick，tasks[] 必须已就绪）；shell 任务先建好但睡，开机画面在 idle 上下文跑完再 `task_wake_shell` + `sched_start`。

## 坑位（都花了时间定位）

1. **`cur` 指针三个切换路径都没更新**（本次最重的 bug）：老代码 `yield()`/`task_timer_tick()` 里都有 `current_task = next`，重写时漏了。症状极具迷惑性：ps 显示 "idle SLEEPING"、A/B/C 里只有恶霸 C 在跑（A/B 状态卡死在 RUNNING 永不回 READY）、start 期间打字 shell 完全饿死、stop 不生效。根因链：shell 入睡时把 idle 标成 SLEEPING、shell 自己留在 RUNNING → IRQ1 唤醒扫描找不到人 → shell 帧存进 idle 的 PCB 又被 C 的帧覆盖 → shell 永远醒不来。**教训：全局"当前任务"指针必须在每个切换点同步更新，帧指针和"我是谁"是两回事。**
2. idle 状态漂移（见"关键设计"3）：不钉死的话 idle 会以 READY 身份混进轮转，白白烧 18Hz 切换。
3. shift 翻译状态可能因 drain 吞掉配对释放码而粘住 → `kbd_drain` 归零 shift 兜底（caps 是自锁键不动）。

## 验证

- **新套件 tools/test-sched.py（15 项）**：调度器启动标记、ps 状态（idle IDLE/shell SLEEPING/ABC SLEEPING）、type-ahead 连敲两条命令都执行、**run count 期间敲 pwd 排队且顺序正确**（串口断言 exit 标记在 [SH] pwd 之前）、start 均衡抢占（A=77 B=79 C=74，恶霸 C 不再垄断）、start 期间打字 shell 可用、stop 冻结、stop 后 shell 存活。
- **8 套老回归全绿**：test-user(36)/font/splash/fs/edit/cc/preempt/mario。preempt 的数字从老架构的 A=131 B=131 C=122（10s）变成 A=186 B=185 C=186（同期），**恶霸 C 也拿到公平份额**——老调度器的"跳过 IRQ1 窗口"hack 曾让 C 占便宜。
