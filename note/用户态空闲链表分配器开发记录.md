# 里程碑 16：用户态空闲链表分配器

> 该功能最初在并行分支编号为里程碑 13，合并远端里程碑 12–15 后统一顺延为 16。

日期：2026-11-07

## 目标

里程碑 12 的 `malloc` 是只能向前的 bump allocator，`free` 是空操作。本里程碑把用户堆升级为可回收的分配器：

1. `malloc/free` 支持块复用；
2. 空闲块按地址排序，支持分裂、相邻合并和堆尾收缩；
3. 增加 `calloc/realloc`；
4. 保持每个进程的用户堆和 allocator 状态互相隔离。

## 块格式

每个块有 16 字节头，payload 以 8 字节对齐：

```text
offset 0  size      含块头的总字节数，始终为 8 的倍数
offset 4  next      空闲链表指针；已分配块不使用
offset 8  magic     分配态 / 空闲态标记，用于拒绝重复 free
offset 12 reserved  保证块头为 16 字节
offset 16 payload
```

堆不额外保存全局块头数组。块头直接放在块前面，所以 allocator 只需要 `brk`、空闲链表头以及少量元数据。

## malloc：首适配、分裂、扩堆

新块大小按 `align8(sizeof(header) + requested)` 计算。`malloc` 依次检查：

1. 从空闲链表头部开始寻找第一个足够大的块；
2. 剩余空间还够放一个最小块时，在原块尾部切出新的空闲块；
3. 空闲链表没有合适块时，调用 `sbrk` 扩展用户堆。

`sbrk` 新增区域会清零，因此首次从断点扩出来的 `malloc` 内存初始为零；已经被复用并写过的块不保证清零，需要清零时使用 `calloc`。

## free：有序插入、合并、收缩

`free` 先校验 payload 落在当前用户堆范围内且块头 magic 正确，然后把块按虚拟地址插入空闲链表：

- 与后一个空闲块首尾相接时合并；
- 与前一个空闲块首尾相接时合并；
- 如果合并后的块正好位于堆尾，就反复调用负增量 `sbrk` 收缩断点。

重复 `free` 会看到空闲 magic，直接成为无操作。非法指针和不属于堆范围的指针也不会被当成块头使用。

## calloc 与 realloc

`calloc(count, size)` 先检查 32 位乘法溢出，再分配并逐字节清零。

`realloc` 的三种路径：

- `realloc(NULL, n)` 等价于 `malloc(n)`；
- 新大小不超过原块容量时原地返回；
- 扩容时分配新块、复制原 payload、释放旧块。

当前缩容不会切分原块，目的是保持实现简单；释放整条堆尾时仍能通过 `free` 收缩 `brk`。

## fork 与进程隔离

allocator 的空闲链表指针和堆游标是用户程序 `.bss` 中的静态变量。`fork` 会复制用户程序低 64KB（包含这些变量）和当前已用堆，因此父子进程获得相同的堆布局与 allocator 状态，但后续修改落在各自独立的物理页。

## 踩坑：GCC 自动生成了用户态不支持的 SSE

首个版本在 32 位结构体赋值时被 GCC `-O2` 自动向量化，生成了 `movq xmm0, ...`。用户程序第一次 `#UD` 的 EIP 正好指向这条指令。

内核没有启用 `CR4.OSFXSR/OSXMMEXCPT`，所以用户态不能假定 SSE 可用。修复方式是在用户程序编译参数中加入：

```make
-mno-mmx -mno-sse -mno-sse2
```

这样 GCC 仍可使用普通整数和 x87 指令，但不会生成需要 SSE 状态初始化的代码。
