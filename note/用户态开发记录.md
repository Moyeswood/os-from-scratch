# 里程碑 10：Ring 3 用户态 — 开发记录

**日期**：2026-11-02 晚 ~ 2026-11-03 凌晨
**状态**：已验证（test-user.py 36 项 ALL PASS + 7 套回归全绿）

## 一、目标

之前 9 个里程碑全部跑在 Ring 0（CPL=0）——shell、游戏、编辑器、编译器都直接碰内核内存。本次补上 OS 最核心的一块拼图：**用户态**。

```
run hello    第一个用户进程 (CPL=3), 全走 int 0x80 系统调用
run count    演示用户态下 IRQ0 定时器照常滴答
run crash    故意写 0xB8000 → #PF → 内核杀进程回 shell
run div0     故意除零 → #DE → 同上
run echo     键盘回显 (ESC 退出), 内核替用户轮询 8042
run badptr   给系统调用传内核指针 → 内核拒绝 (参数校验)
```

## 二、设计决策

**1. 共享地址空间，靠 U/S 位保护（不切 CR3）**

内核 0~32MB 恒等映射保持 supervisor（U/S=0），新增页表把 32~36MB 映射为 USER（U/S=1），用户程序链接在 0x2000000。一个页目录走天下：

- 用户态访问内核页 → #PF（页表项 U/S=0，CPU 硬性拒绝）→ 异常处理器杀进程
- 用户态发生中断/系统调用时内核页都还在，处理器无需切换页表
- 真实 OS 给每个进程独立页目录（隔离更彻底）——留作下一步

**2. TSS.esp0 = 进入用户态那一刻的内核栈**

用户进程跑在 shell 的键盘中断处理链里（和游戏同款架构）。`enter_user` 在 iret 前把 **当时的 esp** 写进 TSS.esp0：用户态期间来的中断/系统调用/异常全部落在那条连续的内核调用链栈上。**所以异常处理能直接 longjmp 回 shell 的命令执行流程**（cc.c 编译器错误退出同款手法）——栈是连续的，一收就回到 `user_run` 的 setjmp 点。

**3. 系统调用：int 0x80，门 DPL=3**

IDT 0x80 号门用 0xEE（DPL3）——用户态唯一的内核大门。硬件异常门保持 DPL0：软件 int n 会查 DPL，但 **CPU 自己触发的异常不受门 DPL 限制**，用户态崩溃照样进得来。调用约定：eax=调用号，ebx/ecx/edx=参数，返回值写回帧的 eax 槽（pusha/popa 恢复）。

**4. 用户程序 = 宿主 gcc 编译 + incbin 嵌入**

`user/*.c` 由宿主 gcc -m32 独立编译（-ffreestanding -nostdlib），链接脚本 `user/linker.ld` 把代码/数据全部定在 0x2000000，objcopy 成 flat bin 后 `user_embed.asm` incbin 进内核，`run` 命令拷到用户区执行（和实模式跳板同款手法）。

## 四、坑位记录（按发现顺序）

1. **kernel.bin 破 100KB 上限**。加完 gdt/tss/异常/6 个内嵌程序后 107KB，boot loader 200 扇区=100KB 装不下 → 尾部未加载，用户区代码取指野指针。扩到 300 扇区（150KB），CHS 循环逻辑本身支持（头/柱面推进已实现）。

2. **`exc.o` 命名冲突**。Makefile 里 `exc.o: exc.asm`（显式规则）和 `%.o: %.c`（模式规则）抢同一个目标，make 优先显式规则 → exc.c 从没被编译 → `exc_dispatch` undefined。asm 改名 `exc_asm.asm` 解决。

3. **sys_getkey 的 hlt 死锁**（echo 程序卡死）。int 0x80 是中断门，进入时 CPU 清 IF；hlt 在 IF=0 下**连 IRQ0 都进不来，永远不醒**。游戏主循环为什么没事？因为 vga_putc 尾部有 `sti`（每次打印都把中断重新打开），hlt 前 IF 恰是 1。修复：`sti; hlt` 组合——开门睡，IRQ0 每 55ms 唤醒一次再查 8042。

4. **GDT 内核数据段 D 位**。数据段 gran 字节写 0x8F（D=0）→ SS 被当成 16 位栈（push/pop 用 SP）→ 一进中断就崩。必须 0xCF（D=1）。用户段同理。

5. **TSS 布局一字不差（104 字节）**。32 位 TSS 每个 16 位字段后面都有保留字，iomap_base 在偏移 0x66。加了编译期断言 `sizeof(tss_t)==104` 防手滑。**iomap_base 必须 ≥ TSS limit（0x68）**：表示"没有 I/O 权限位图"→ 用户态任何 in/out 都 #GP。留 .bss 的 0，CPU 会把整个 TSS 当位图且全 0 = 所有端口对用户开放——段/页/IO 三道特权边界漏一道。

6. **用户态异常必须装 IDT 门**。之前 0~31 号全是空门：用户态一崩就是 #GP（空门）→ 三重故障 → 复位循环，什么都看不见。32 个异常桩全部装上后，crash 程序能打印完整现场（EIP/CS/EFLAGS/ESP/CR2 + 错误码解读）。

7. **异常输出的串口镜像**。`put_hex32` 一开始只写屏幕（vga_putc），串口只看到 "CR2=" 后面是空的——测试预言机（串口）看不见现场，断言全挂。修正为双通道输出。

8. **用户程序的 blob 大小是链接期常量**。`user_hello_end - user_hello_start` 不能写进 C 初始化器（不是编译期常量，clang 直接拒绝）→ 程序表改运行时填充（`user_progs_init`）。

9. **从用户态回来的段寄存器**。enter_user 把 DS/ES/FS/GS 换成 0x23（DPL3）。exit 系统调用/异常 longjmp 回 user_run 后，内核代码还挂着用户段——平坦模型下能跑，但"内核不该挂 DPL3 段"，setjmp 分支里显式换回 0x10。

10. **PDE 的 U/S 位**。用户页表项设了 PAGE_USER 但页目录项忘了——CPU 查两级，任何一级是 supervisor 用户态访问都 #PF。PDE8 也要 `PAGE_USER`。

11. **sys_puts 读越界 DoS**。首指针校验挡不住"字符串一直延伸到用户区外"——内核会读到 36MB 外的未映射页 → 内核态 #PF panic（用户程序可借此把内核搞停）。读循环限在 `USER_BASE+USER_SIZE` 内，越界截断返回。

## 五、架构要点（教学）

**保护边界三层**：
1. **段**：用户段 DPL3，想 ljmp 进内核段 → #GP（`crash` 变体可演示）
2. **页**：U/S 位——用户态碰内核内存 → #PF（`run crash` 演示：写 0xB8000，错误码 U=1 W=1，CR2=0xB8000）
3. **系统调用参数**：用户让内核"帮忙读"内核地址 → 内核校验指针落在用户区（`run badptr` 演示）

**中断在用户态照常走**：enter_user 把 iret 帧的 EFLAGS.IF 置 1，IRQ0 每 55ms 进内核加滴答再回来，用户程序无感但可通过 SYS_GETTICKS 观察（`run count` 演示）。用户进程跑在 IRQ1 服务窗口内，调度器按老规矩跳过抢占——单用户进程跑完为止。
