## 一、设计

320x200 模式 13h，16x16 图块，12 行 × 160 列关卡（顶部 8px HUD + 192px 游戏区）。卷轴镜头（平滑跟随）+ 视差背景（云 1/3、山 1/2）。物理全定点数（8.8 定点，免浮点）：跑速 2.5px/滴答、跳跃初速 -7、重力 0.42（跳跃高约 58px = 3.6 格，滞空 1.8 秒）。板栗仔 0.5px/滴答、撞墙回头、走下悬崖、可踩扁。金币/问号块/水管/楼梯/旗杆，HUD（分数/金币/时间/命），蜂鸣音效。

运行环境与 tetris 相同：游戏跑在 IRQ1 处理器内（按键轮询 8042、ISR 保护免疫抢占），IRQ0 滴答驱动。

## 二、三个真 bug（都藏在测试失败里）

### 1. 忘了加重力（低级但致命）

初版 update() 里没有 `vy += GRAV`——vy 恒 0 → on_ground 恒 0 → 跳跃条件 `jump_pressed && on_ground` 永不成立，马里奥永远悬空。**教训：写完物理先让马里奥"掉下来"再测跳跃。**

### 2. 瞬时按下+释放对在同一轮轮询里被吞

sendkey 注入的是"按下+释放"一对事件，游戏一次轮询就把两个字节都读走了——held_jump 1→0，跳跃沿丢失（tetris 不受影响因为它直接响应按下事件，mario 需要"按下沿"）。**修复：`jump_pressed` 锁存，按下即置位，update 消费后清零。**

### 3. on_ground 每滴答闪烁 → 跳跃锁存 50% 概率被丢（最难查的海森堡 bug）

站立时重力每滴答把脚底推下 0.42px（y=183.42），落地检测只看脚底本身 → 还没跨入地面行（184）→ og=0；下一滴答 +1.26px 跨过 → og=1。**og 隔滴答闪烁，跳跃锁存随机落在 og=0 的滴答上被无条件丢弃（丢 50%）。** 串口调试打印改变了滴答相位，让锁存恰好落在 og=1 上——打印代码"修好"了 bug，去掉打印就复现，典型的 Heisenbug。

**修复：落地探测脚底 +1px 余量**（`solid_at(xx, feet + 1)`），站立时每滴答稳定落地，og 恒 1。板栗仔同款修复。

## 三、主循环的两个设计点

1. **丢帧追赶**：渲染一帧要 2-5 个滴答（TCG 下约 15 万次 putpixel），主循环跟不上 18Hz——`while (g_ticks != last) { last++; update(); }` 把漏掉的滴答全部补上，游戏时间严格按滴答推进（否则游戏越跑越慢且节奏抖动）。
2. **frame_dirty 门控**：状态没变不重绘（暂停后一帧收敛、空闲省 CPU）。

## 四、测试方法（重要，以后都能复用）

无头 QEMU + monitor 注入按键 + xp 读帧缓冲验证（同 tetris）。马里奥特有：

- **sendkey 支持按住**：`sendkey d 1200` = 按下 1.2 秒（hold_ms 参数），实测滴答精确
- **帧缓冲落后于游戏状态**（渲染慢 + 逐行 xp 读取慢）：测量前**用 P 暂停冻结 → 等 ~1 秒让渲染收敛 → 再读**，否则读到旧画面（实测差 7 滴答 = 17px）
- **QEMU monitor 活动会暂停 VCPU**：xp 命令风暴期间游戏滴答冻结（BQL 竞争，[P] on/off 同一滴答为证）——扫描后要留沉降时间，且测量窗口不能跨扫描
- **无敌帧闪烁**（重生后 90 滴答）会让扫描落空：多等 5 秒 + 重试扫描
- **像素级验证**：马里奥红色（索引 18）唯一，全屏扫红色 bbox 即马里奥位置；跑动 55px/1.2s、跳跃 y 127 空中、掉坑重生 x=32 全部可精确断言

测试脚本：`/tmp/test-mario.py`。

## 五、遗留

- TCG 下渲染约 2-5 滴答/帧，游戏约 4-9 fps——真机/KVM 会流畅很多；教学场景可接受
- 关卡为单关；美术是字符画（`mario.c` 里的像素画全是可编辑的字符数组，改美术不用懂任何格式）
- 音效与 tetris 共用 beep()；马里奥没有长大/花等状态（范围控制）
