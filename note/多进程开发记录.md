# 里程碑 11：多进程 — 独立地址空间 + fork + 后台进程

日期：2026-11-03（11a 调度器重构 + 11b 多进程，同一天完成）

## 11a：PCB 调度器 + 键盘环形缓冲

见 `note/调度器重构开发记录.md`。一句话：shell/游戏/编辑器/cc/用户程序全部从 IRQ1 处理链里搬出来，shell 变成内核线程，键盘走环形缓冲。这是 11b 的地基——用户进程要成为"真正的任务"，调度器和输入必须先到位。

## 11b：用户进程 = 调度任务

### 架构

```
进程物理布局 (一次 alloc_pages(1026) 的连续 4MB+8KB 块):
  [0]      页目录 (1 页) — PDE0-7 复制内核 (恒等映射 0~32MB) + PDE30 草稿窗口 + 自己的 PDE8
  [1]      页表 8   (1 页) — 用户区虚拟 32~36MB → 本进程自己的物理页 (USER 标志)
  [2..1025] 用户区   (4MB)

切换任务 = 换上下文帧 + (若是用户任务) 换 CR3 + 设 TSS.esp0 = 它的内核栈顶
```

**关键设计**：

1. **52 字节用户帧**：8 寄存器 + EIP + CS + EFLAGS + **ESP(用户) + SS(用户)**。iret 看到 CS.RPL=3 会自动再弹 ESP/SS 落回用户栈——和内核任务的 44 字节帧共用同一套 popa+iret 恢复代码，switch.asm/irq.asm 一行没改。fork 的白嫖：int 0x80 帧 (user_frame_t) 的布局恰好就是 52 字节用户帧——直接抄到子进程内核栈、eax 槽改 0，子进程第一次被调度就落在"int 0x80 之后一条指令"，看到 fork() 返回 0。
2. **草稿窗口**（paging.c）：新进程的物理页在 32MB 之外，内核恒等映射够不着。固定虚拟窗口 0x7800000（PDE30→PT30）把目标物理页临时映进来写，用完摘掉。**所有页目录都挂同一个 PT30**（内核代码在谁的 CR3 下都能用窗口——fork 在父 CR3 下拷贝时就用得上）。★必须 cli 成对使用：窗口是全局共享的，任务 A 映到一半被抢占、任务 B 又映别的目标，A 恢复后写错地方。
3. **退出 = ZOMBIE + 切走**（task_zombie_switch_away）：退出/被杀只标状态并换走，**不释放内存**——退出瞬间还跑在它自己的 CR3 下，释放页目录会炸。物理块由父进程 proc_wait 收尸时释放（父跑在自己的 CR3 下）；孤儿僵尸（后台进程）在下次 spawn 时统一清扫。kill 命令直接把任务标 ZOMBIE（跑着就跑到下一个滴答，睡着就永远睡）。
4. **教学简化：只初始化程序实际用到的区域**——spawn 清零低 16KB（镜像+BSS 预算）、fork 复制低 16KB + 栈区（顶部 64KB，子进程恢复现场后要用父进程的调用栈）。中段 4MB 页映射但不初始化（真实 OS 用按需零页/写时复制，留作引子）。
5. **前台/后台**：`run hello` = spawn + proc_wait（睡 WAIT_PROC，子退出唤醒）；`run hello &` = spawn 完就回 shell。新增 syscall：SYS_FORK/GETPID/SLEEP。

### 新用户程序

- **forkdemo**：fork 后子进程把全局 counter 改 200，父进程的还是 100——同一份代码同一个变量名，各自的内存。测试断言输出顺序（子改完父才打印）。
- **spinner**：无休止打点（sleep(2) 滴答），`run spinner &` + ps + kill 的演示载体。

### 坑位

1. **proc_fork 先用后赋值**：`uint32_t* stack = (uint32_t*)child->kstack_top;` 写在 `child->kstack_top = ...` **之前**——新槽位 kstack_top=0 → 往 0xFFFFFFFC 写 → 内核 #PF panic。先设栈再建帧。
2. **pick_next 的 ZOMBIE 回退**：原来只有 `!= TASK_SLEEPING` 就返回 cur——ZOMBIE 会被选回自己、僵尸切不走，防御循环里 sti;hlt 卡到天荒地老（现场：EIP 卡在 sched_start、串口静默）。改完条件后 ZOMBIE → idle。
3. **idle 永远不领状态**：三个切换路径里 `next != &tasks[0]` 才写 RUNNING，否则 idle 被降成 READY 混进轮转队列。
4. **splash 释放码跳过动画**（11a 的债）：kbd_drain 不再空转等释放码——触发 `splash` 命令的回车释放码还在 8042 传输途中，drain 后晚到环形缓冲，被 splash_anykey 当"任意键"秒跳动画，随后测试的跳过键污染 shell 输入（`apwd` → Unknown command）。修法：splash_anykey **只认按下码**（测试 4 连跑全绿前 1/3 概率 FAIL）。
5. **测试基建大排查**（花的时间比内核代码还长，结论值得记）：
   - **串口窗口切行**：mark_serial_base() 的窗口起点可能恰好落在正在到达的标记行中间——"[PROC] swept" 变 "ROC] swept"，子串匹配失败。现象极具迷惑性：标记明明在全局日志里、窗口里就是没有。修法：窗口起点留 64 字节余量。
   - **monitor socket stale 响应**：send() 超时会留下半截响应，下一次 send 读到残留 "(qemu)" 提前返回，测试节奏和监视器处理节奏脱钩。修法：发送前排空（短超时 0.3s）。
   - **检查过早的竞态**：fork 的后续循环、双后台 spawn 计数都是快照式断言，改成 wait_for。
   - **QEMU 11.1.2 串口怪癖（未解但已定位边界）**：用户态异常杀进程后"紧跟着"（~0.1s 内）发的键，串口输出会整段延迟/消失到下一次串口输出或 QEMU 退出才浮现。用零延时内存日志证明**内核完全正确**（键收到、命令执行、UART 没卡），问题在 QEMU 仿真层；测试避开该时序即可。
