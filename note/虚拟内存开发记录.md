# 里程碑 13：虚拟地址空间、按需分页与 COW

日期：2026-11-06

## 结果

用户进程不再一次性占用 4MB 连续物理块。每个进程只有独立页目录和
实际触及的页表；flat 镜像页在 spawn 时装入，栈、堆和 mmap 页在首次
访问时由 #PF 补零。

fork 先让父子页表共享物理页并清除 `PAGE_WRITE`、设置软件 COW 位。
任一方写入时分配新页、复制 4KB、修正引用计数并恢复写权限。进程退出
后由父进程或孤儿清扫销毁整棵页表。

栈底保留一个永久不存在的 guard page。合法栈增长按页分配，越界写会
被 VM 层拒绝并杀掉进程；Shell 继续运行。

## 接口

```c
void* brk(void* new_break);      // 返回旧断点
void* mmap(uint32_t length);     // 匿名映射，首次访问补页
```

新增演示：

```text
run vmtest   # 栈/堆/mmap 补页 + fork COW + brk 收缩
run vmguard  # 故意写 guard page，观察 #14 现场
```

## 踩坑

1. 新任务在页表和初始帧完成前必须保持 IDLE；提前标 READY 会让定时器
   切进半初始化地址空间。
2. COW 要先完整建立子页表，再统一冻结父 PTE；失败时才能安全回滚。
3. fork 后必须刷新父 CR3 的 TLB，COW 单页处理使用 `invlpg`。
4. brk 收缩后继续读取旧堆会按设计触发 #PF；测试应在收缩前保存值。
5. syscall 的用户指针要逐页验证映射，不能只检查虚拟范围。
