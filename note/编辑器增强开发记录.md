# 里程碑 14：编辑器光标修复与功能增强

日期：2026-11-07

## 问题：换行后上一行残留光标影子

旧渲染逻辑对每个格子只比较字符缓冲偏移：

```c
vga_putc_attr_xy(x, y, c, src == ed_cur ? 0x70 : 0x0F);
```

输入 `abc` 后按 Enter，新光标偏移是 4。上一行虽然只有 3 个字符，但渲染器仍会扫描该行的 80 个屏幕格；第 4 格刚好满足 `src == ed_cur`，于是也被画成反显，形成“影子”。

修复方式是先计算光标的真实行列，只允许“当前行 + 当前屏幕列”这一格反显。行尾空白的可视光标也走同一条路径，不再依赖字符缓冲偏移碰巧相同。

自动测试直接读取 VGA 文本显存属性：

- 第 1 行所有属性都不是 `0x70`；
- 新行的光标列属性是 `0x70`。

## 撤销 / 重做

新增 128 项操作历史，每项记录：

- 插入或删除；
- 字符和缓冲偏移；
- 操作前后光标；
- 操作前后状态序号；
- 编辑分组。

连续输入共用同一个编辑分组，所以一次 Ctrl+Z 会撤销整段输入；Tab、删除和导航会切断分组。Ctrl+Y 按原顺序恢复。

状态序号同时用于判断 `[M]`：撤销回保存点会自动清除修改标记；保存后继续编辑、撤销和重做也能正确反映磁盘内容是否仍与缓冲区一致。

## 搜索 / 跳行 / 按词导航

- `Ctrl+F`：在消息行输入文本，从当前光标向后查找并循环回文件开头；命中后跳到匹配起点。
- `Ctrl+G`：输入 1-based 行号，越界时夹到最后一行。
- `Ctrl+方向键`：向前或向后跳过整词。
- `Ctrl+Backspace` / `Ctrl+Delete`：按词删除，整个范围作为一个撤销分组。

## 同时修复的边界问题

1. 单行文件按“下”不再错误跳到行尾。
2. 上下移动以真实行尾为边界，不把换行符当成可显示字符。
3. 保存点与当前状态使用序号比较：撤销到已保存内容时会自动清除 `[M]`，保存后从旧状态分叉编辑也不会误判为已保存。
4. 内核 `-O0` 下 GCC 也会为 28 字节结构体复制生成 SSE `movdqu/movups`；内核没有启用 SSE，实际触发 `#UD`。现在只对 `kernel/editor.c` 使用 `-mno-mmx -mno-sse -mno-sse2`，用户程序沿用里程碑 13 的同组参数。曾尝试把它们加到所有内核 C 文件，结果只是让调度测试中的 2000 万次 volatile 忙等明显变慢，因此最终把改动范围缩小。

`tools/test-edit.py` 从 49 个实际断言扩展到 67 个，全部通过。新增覆盖：

- 输入多行后 VGA 显存中的光标残影；
- 连续输入整段撤销与重做；
- 搜索命中后插入；
- 跳转到指定行后编辑；
- Ctrl+方向键与 Ctrl+Backspace 的组合行为。

原有文件打开/保存、方向键、Home/End、PgUp/PgDn、Delete/Backspace、Tab、退出确认、错误路径、字体和游戏回归均继续通过。
