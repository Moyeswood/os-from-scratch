## 一、目标与方案决策

原定目标：在 NewOS 里跑俄罗斯方块。`tetris/tetris.asm` 已有 1435 行纯实模式汇编版（完整功能：7-bag、wall kick、锁定延迟、暂存、消行闪烁、5 套主题、蜂鸣）。

**方案选择（此前"待定"的决策）**：选了 **A — C 移植进保护模式**。理由：
- graphics.c 已能在保护模式下画模式 13h，原版依赖的 BIOS INT 16h（键盘）/INT 1Ah（时钟）/INT 10h（文字）在保护模式内核里全都没有
- 实模式跑 asm 需要把整个游戏塞回低内存、绕开内核，以后马里奥也没法复用
- C 移植正好配合用户正在学的 C 课程

## 二、新增组件

| 文件 | 作用 |
|---|---|
| `kernel/timer.c/h` | PIT 通道 0 → IRQ0，约 18.2 Hz 滴答（分频 65536，和 BIOS INT 1Ah 滴答频率一致，游戏计时逻辑可 1:1 对照移植）；PC 扬声器蜂鸣（通道 2 + 0x61），响 2 滴答自动关 |
| `kernel/tetris.c/h` | 游戏本体（约 700 行），逻辑 1:1 对照原版 asm：7-bag（Fisher-Yates + 16 位 LCG）、wall kick（0,+1,-1,+2,-2）、锁定延迟 7 滴答/最多重置 15 次、重力 11-等级 滴答/格、消行闪烁、5 套主题、10 级边框色、蜂鸣音效 |
| 改动 | `irq.asm`（irq0_handler）、`idt.c`（门 32）、`pic.c`（开放 IRQ0，掩码 0xFC）、`kernel.c`（timer_init）、`shell.c`（tetris 命令）、`Makefile` |

**行为改动**：原版 ESC 通过 8042 复位整机，改为退出游戏回 Shell（游戏结束画面 R 重新开始不变）。

## 三、★架构要点：游戏运行在 IRQ1 处理器内部

Shell 的命令分发在 `keyboard_handler`（IRQ1）里完成——回车触发命令，`execute_command` 在**键盘中断处理函数内部**执行。所以整个游戏跑在 IRQ1 处理器的上下文中。由此引出两个关键设计：

1. **游戏按键必须轮询 8042**（`game_key()` 直接查 0x64/读 0x60），不能靠键盘中断——8259A 不会再次投递同优先级的 IRQ1（ISR1 已置位）。这和 testmode 的"按任意键"是同一个模式。
2. **IRQ0（定时器）优先级高于 IRQ1，会正常嵌套投递**——游戏主循环 `hlt` 睡眠，靠每个滴答唤醒检查重力，省 CPU。实测游戏内滴答率 18.3 Hz（95 滴答/5.2 秒），与预期一致。

顺带的推论：游戏期间 shell 的输入缓冲不会被污染（IRQ1 被阻塞，`keyboard_handler` 根本不执行）；游戏退出后可能补投递一个"迟到"的 IRQ1（ESC 释放码残留），读到的字节被正常忽略，无害。

## 四、调试记录

### 坑：QEMU 11.1.2 的 pmemsave 坏了

`pmemsave 0xa0000 64000 /tmp/xx.bin` 报 `invalid char 't' in expression`——**文件名被当成表达式解析**（把路径换成 `/x.bin` 报错字符就变成 'x'，铁证）。旧会话（22:24 的 /tmp/fb.bin）能成功，说明是 QEMU 版本/环境变化，不深究。**结论：验证显存一律用 `xp /Nwx` 分块读**（`/800wx` 一次 3200 字节，瞬时且完整），与记忆里的经验一致。

### 测试假象：逐行 xp 读取污染测量

第一版测试逐行读帧缓冲（164 次 monitor 往返 ≈ 3.4 秒/帧），读着读着方块还在下落，bbox 变成多个时刻位置的并集——误判"重力 3.5 倍速"、"软降后方块上移"。**解法：用游戏的 P 暂停键冻结画面再读**，或收窄读取窗口。最终测试：

1. 标题 7 色方块 ✓
2. 重力 = 2.2 秒 4 格（与原版节奏一致）✓
3. 左移 8px ✓ 软降 8px ✓
4. 边框色 9 ✓ NEXT 预览 ✓
5. ESC → BDA 0x449 = 0x03 ✓
6. Shell 回归（help 全屏 2000 字符）+ testmode 往返 ✓

测试脚本：`/tmp/analyze-tetris.py`（monitor socket 驱动，可复用）。

### 边界注意

- 软降/重力测量窗口 < 0.55 秒（10 滴答）才不会被重力混入
- ESC 退出后要排空 8042（释放码残留，testmode 同款坑，shell.c 已处理）
- 退出游戏前 shell 侧无需任何输入保护（见第三节推论）
