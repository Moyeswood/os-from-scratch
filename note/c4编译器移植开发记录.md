## 移植方案（宏桥接，原版 528 行近乎逐字保留）

- 原版 github.com/rswier/c4：next() 词法 → expr() 优先级爬升 → stmt() → 栈式 VM eval()。
- **宏桥接**：`#define printf cc_printf` / `malloc cc_malloc` / `memset cc_memset` / `memcmp k_memcmp` / `open/read/close cc_open/cc_read/cc_close` / `exit(x) cc_exit(x)`——主体代码与原文逐字一致，适配全在桥接层。
- **cc_printf**：迷你 printf（%d 宽度零填充/%s/%c/%%），输出**屏幕 + 串口镜像**（串口是测试预言机）。
- **exit(-1) → `__builtin_longjmp`** 回 cc_run 的 setjmp 点（freestanding 无 libc setjmp；clang 要求 longjmp 参数为常量）。
- **VM 内存池**（sym/text/data/stack/heap 各 64KB）：memory.c 新增 **alloc_pages(n) 连续多页分配**（VM 池是连续地址空间，逐页 alloc_page 不保证连续！），用完逐页释放。
- **open/read/close 对接文件系统**：fd = inode 号，读取位置按 fd 记录——编译出的 C 程序能读 OS 里的文件（测试：C 程序 open+read 一个 echo 写出来的文件）。
- **ESC 失控保护**：VM 每 16384 条指令查一次 8042，ESC → "interrupted at cycle N" → 返回 shell（原版死循环只能整机复位）。
- 去掉原版 -s 源码回显/-d 调试（宿主机特性）；源文件上限 16KB；`#define int long long` 移除（32 位平台用原生 int）。

## 踩坑

1. `k_memset` 返回 void 而原版 memset 返回指针 → PRTF/MSET 行 `a = (int)memset(...)` 编译错 → 包一层返回指针的 cc_memset。
2. `close` 宏漏定义 → 隐式函数声明错误。
3. cc_printf 返回 void 而原版 printf 返回 int（PRTF 赋值用）→ 改 int。
4. 测试侧：**错误路径不打印 exit()**，run_cc 必须等具体错误串而不是统一等 exit(；echo 写文件带尾随 \n（read 返回 15 不是 14）。
