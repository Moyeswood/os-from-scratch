# 抢占式多任务（Preemptive Multitasking）开发记录

> 日期：2026-10-28
> 状态：✅ 已完成并验证（9 项测试全过，含 tetris/testmode 回归）
> 对应提交：feat(task): PIT IRQ0 抢占式调度

---

## 一、目标

协作式多任务（yield 轮转）有一个致命弱点：任务若忘记 yield（忙等循环、死循环），整个系统就饿死。本里程碑在 PIT IRQ0（18.2 Hz）里加调度：**每个滴答自动切换任务**，谁也饿不死。

验证手段：新增演示任务 C（"恶霸"）——纯忙等循环、从不 yield。`start` 后 A/B/C 同时出现在屏幕上（10 秒内 A=131 B=131 C=122）→ 恶霸被打断，抢占成立。`stop` 后画面完全冻结。

## 二、核心设计

### 统一 44 字节上下文帧

```
+0  .. +31   8 个通用寄存器 (popa 顺序)
+32 .. +35   EIP
+36 .. +39   CS
+40 .. +43   EFLAGS
```

恢复方统一用 `popa + iret`，所以**协作式（switch_task）和抢占式（irq0_handler）产出的帧可以互相恢复**——一个被 yield 保存的任务可以被定时器恢复，反之亦然。

- `switch.asm` switch_task：pusha 后返回地址恰好落在 EIP 槽（+32），只需补写 CS(+36)=0x08、EFLAGS(+40)=0x202，保存帧 → 载入下一帧 → popa → iret
- `irq.asm` irq0_handler：中断门进来时 CPU 已压 EIP/CS/EFLAGS，pusha 后天然就是完整帧。把帧指针 push 给 C，`timer_handler` 返回下一帧指针，`mov esp,eax → popa → iret`
- `task.c` create_task：初始帧 = 8 个 0 + EIP=入口 + CS=0x08 + EFLAGS=0x202，首次恢复即进入任务函数

### 调度策略

- 每滴答轮转：kernel → task_a → task_b → task_c → kernel（时间片 ≈ 55ms）
- `task_timer_tick(esp)`：未启动（multitasking_enabled=0）原样返回；**若 8259A ISR 有其他中断在服务中（读 OCW3），跳过抢占**——Shell 命令和俄罗斯方块都跑在 IRQ1 处理器内部，不能被定时器从中间切开
- yield 在切换期间 cli/sti，防止 IRQ0 在切换中途二次抢占

## 三、踩过的坑（两个都让内核三重故障重启循环）

### 坑 1：switch.asm 的 pushf 帧错位

初版想保存真实 EFLAGS，用 pushf 压栈再挪位——但 pushf 压在了帧顶（+0，即 EDI 槽），我却按 [esp+32] 去读，还把 CS 写进了返回地址槽。iret 恢复垃圾 EFLAGS → #GP → #DF → 三重故障 → QEMU 复位循环（串口日志 Paging 消息 808 遍）。

**修复**：不需要 pushf——pusha 后返回地址已在 EIP 槽，只需补 CS/EFLAGS。EFLAGS 硬编码 0x202（IF=1）是安全的：yield 里 cli 后 IF=0 被保存的帧，恢复后由 yield 尾部的 sti 重开中断；初始帧和定时器保存的帧本来就该 IF=1。

### 坑 2：帧指针参数的双重 +4 修正

irq0_handler 里 `mov eax,esp; push eax` 压栈的是**帧指针的值本身**，C 收到的参数就是帧指针——我却按"参数 = 帧指针 - 4"又加了 4。定时器恢复的帧整体偏移 4 字节，iret 弹出错位的 CS（错误码 0x214，超出 GDT limit 0x17）→ 又一个复位循环。

**定位方法**：QEMU `-d int -D log` 抓异常日志——第一个 IRQ0 后立刻 #GP，EIP=iret、ESP 比预期多 4，一眼看出帧偏移。另发现：**BIOS 时代 PIT 在 PIC 里遗留了挂起的 IRQ0**，sti 后立刻投递（内核启动瞬间、EIP 还在 kernel_main 里）——所以"未启用时不切换"的路径必须在开机早期就正确。

## 四、验证结果

- `start` 后 10 秒：A=131 B=131 C=122 同时出现（C 从不 yield，A/B 继续打印 = 抢占生效）
- `ps` 在 start 期间可用（4 任务，ISR 保护下输出不被切碎）
- `stop` 后画面计数完全冻结 (164,159,149) → (164,159,149)
- tetris 全量测试 9 项全过（ISR1 保护：游戏期间定时器不抢占，重力节奏 2.2s 4 格不变）
- testmode 往返回归通过

测试脚本：`tools/test-preempt.py`（与 `tools/analyze-tetris.py` 同一套 monitor 驱动）。

## 五、遗留说明

- A/B/C 与 Shell 共享 VGA 光标：任务切换可能发生在 vga_putc 中途，输出偶尔交错——这是没有锁的经典竞态，教学上正好作为下一步（同步原语/用户态）的引子
- 时间片固定 1 滴答（55ms），没有优先级；调度器在 task.c，扩展方便
