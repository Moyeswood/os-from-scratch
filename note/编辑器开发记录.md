# 内置文本编辑器开发记录

日期：2026-10-29。里程碑 7：nano 风格内置编辑器（`edit` 命令），38 项测试 ALL PASS，fs/字体套件回归全绿。

## 设计

- **架构与游戏同款**：edit 在 shell 里执行 → 编辑器跑在 IRQ1 键盘处理器上下文 → 后续按键不产生新 IRQ1 → **编辑器自己轮询 8042 读原始扫描码**，自己跟踪 Shift/Ctrl/Caps 状态和 0xE0 扩展键前缀。
- **数据模型**：单一字符缓冲 ed_buf[48KB]（= 文件系统单文件上限），行以 `\n` 分隔，光标 = 字节偏移；行号/列号按需线性扫描（48KB 在 TCG 下微秒级）。
- **屏幕**（纯文本模式，无模式切换）：rows-2 行文本视口（80 列、长行水平滚动、光标格反显 0x70）→ 状态栏（反显：`^S Save ^X Exit | L行 C列 | 路径 [M]`）→ 消息行（反显）。渲染走新增的 vga_putc_attr_xy（直写显存，绕过 vga_putc 的每字符 cli/光标同步）+ vga_move_cursor 一次定位。
- **键位**：方向键/Home/End/PgUp/PgDn、Enter、Backspace/Delete、Tab=4 空格、Ctrl+S 保存（截断写 fs_write）、Ctrl+X 退出（**有修改第一次只警告，再按才放弃退出**——nano 风格，无需 y/n 解析）。
- **保存/打开**：fs_lookup 不存在 → fs_create（新建）；fs_read 读入；fs_read<0 = 目录 → 报错返回。退出前 kbd_drain（回车/退出键释放码残留，游戏同款陷阱）。

## 踩坑

1. **★0xE0 扩展键释放序列吞 e0 标志**：扩展键释放 = `0xE0 + 0x8x`，若释放分支不消费 e0，粘住的标志会把下一个**普通键**误当扩展键吃掉——实测 End 之后 backspace 丢一个、shift-1 的 `!` 整个丢（保存内容少字符）。修复：每个分支（含释放）统一清 e0。
2. **Ctrl 组合键的真相**：键盘不区分 Ctrl+S 和 's'（扫描码相同），宿主驱动靠跟踪 Ctrl 键状态自己判断——编辑器必须自己跟踪 0x1D（Ctrl）make/break。
3. 测试侧：**QEMU sendkey 没有大写字母键名**——直接发 `"X"` 被静默丢弃（警告测试"无修改"、行号 L 全丢的假象），必须映射成 `shift-x`；`screendump` 是 monitor 命令不是按键。
4. 编辑器打开标记打印后紧接 kbd_drain（~0.3s 忙等），**测试在标记后 1.2s 内敲的键会被排空吃掉**——run_edit 要留窗口。
5. 状态栏反显 attr 0x70 = ASCII 'p'，屏幕提取时奇数字节（属性）必须跳过。
