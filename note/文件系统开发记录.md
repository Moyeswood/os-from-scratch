# 内存文件系统开发记录

日期：2026-10-29。里程碑 6：内存文件系统 + shell 文件操作命令（pwd/ls/cd/mkdir/touch/cat/rm/echo >/df），39 项测试 ALL PASS。

## 设计（xv6 风格教学版）

- **块 = 页 = 4KB**，FS 共 1MB（256 块），开机 alloc_page 分配 + 格式化（内存 FS，重启重置）。`fs_block[i]` 存逻辑块 → 物理地址（不要求连续，以后换真磁盘只需换这个映射）。
- 布局：块 0 超级块（magic + inode 位图 + 块位图）→ 块 1 inode 表（64 × 64B 恰好一页）→ 块 2 根目录 → 块 3+ 数据。
- inode：type/size/nlink/direct[12]（文件最大 48KB）+ reserved（对齐到 64B）。
- 目录项 32B（inum + 28 字符名字），"." 和 ".." 是真实目录项；路径解析全靠它们（相对/绝对/./.. 统一走）。
- Shell 提示符显示 cwd：`OS:/a/sub>`（fs_pwd 沿 ".." 向上收集名字再反转拼接）。

## 踩过的坑（按发现顺序）

1. **★inode 0 与空槽冲突**（本里程碑最大坑）：目录项用 inum=0 表示空槽，但根 inode 也是 0 → 根的 ".."（指向 0）永远"不可见"→ fs_pwd 走到根下一层就断（提示符 OS:/sub> 而不是 OS:/a/sub>）、dir_lookup(x,"..") 失败、ancestor 检查失灵。**修复：inode 0 永久保留，根 = inode 1（经典 xv6 做法）**。
2. **★fs_readdir 内部跳过空槽 + 调用方 idx+1 的组合**把同一条目读两遍（ls 重复打印）。修复：readdir 改成原始槽读取器，调用方检查 inum==0 跳过。
3. **空目录判定不能用 size**：删除文件留下 inum=0 空槽，size 不变 → `size != 64` 误判"非空"。修复：数有效条目（dir_is_empty）。
4. **★boot loader 只读 100 扇区（50KB）**，加 fs 后内核 58.8KB → 尾部没加载 → fs_block 数组是垃圾指针 → 页错误复位循环（CR2=0xc811e800 一眼看出野指针）。修复：扩到 200 扇区（100KB）+ **BX 16 位回绕修复**（128 扇区 = 64KB 后 `add bx,512` 回绕覆盖内核头部 → 溢出时推进 ES 段）。
5. Shell 重构：整串比较 → tokenize 成 argv 分发（echo/font 参数化，为编辑器/编译器里程碑铺路）。echo 支持 `>` 重定向（首个词截断写、后续追加）。

## 测试基建（tools/test-fs.py，39 项）

- **串口是可靠预言机**：fs 命令打 [SH] 标记（内核日志风格），测试等标记零开销。**屏幕 xp 读取是 BQL 风暴**（冻结 VCPU → 8042 16 字节队列溢出 → 按键丢失 → 命令级联错乱），只能在串口标记确认后静置 0.6s 再敲下一条。
- QEMU sendkey 特殊字符要键名映射（'/'='slash'，'>'='shift-dot' 等），直接发字符被静默丢弃（"/b/sub/x.txt" 变 "bsubxtxt"）。
- 连接后第一条 monitor 命令会被 greeting 吞掉 → drain_greeting()。
- 屏幕抽查最终从套件移除：长会话后期每行输出都触发滚屏（memmove 走 VGA 模拟路径）+ xp 冻结，渲染落后串口 4+ 条命令追不上——基建限制非内核 bug（渲染正确性已隔离复现验证）。

## 顺带的改进

- **真滚屏**（vga_putc 满屏时 memmove 上移一行 + 清末行），替换旧版"直接清屏"——旧版把 20+ 行输出全抹掉（font 测试的 help 检查因此挂过）。
- kernel/string.h：内联 k_memset/k_memcpy/k_strcmp 等（无 libc，编辑器/编译器里程碑复用）。
