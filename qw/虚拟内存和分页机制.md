## 💻 二、 虚拟内存分页机制 (Paging)

### 2.1 核心概念：什么是分页机制？

在开启分页之前，我们的 C 语言指针直接等于物理地址。这非常危险，一个写错的指针就能覆盖内核代码或硬件寄存器。

分页机制的本质：在 CPU 和物理内存之间加了一层“翻译官”（MMU）。CPU 发出的不再是物理地址，而是“虚拟地址”，MMU 负责将其翻译成真实的物理地址。

通俗比喻：图书馆的索引系统 想象物理内存是一个巨大的图书馆，里面有 4GB 的书（物理地址）。 没有分页时：你直接走到书架前找书（直接访问物理地址）。 有分页时：你不能直接去书架。你必须先查总目录（Page Directory），目录告诉你去哪个分册（Page Table），分册再告诉你具体的书架位置（Page）。

x86 分页的三级结构 在 32 位 x86 系统中，32 位的虚拟地址被 MMU 强行拆分成三部分：

高 10 位 (31-22)：10 bit，索引 页目录 (Page Directory)，比喻：查“总目录”，找到第几本分册。 中 10 位 (21-12)：10 bit，索引 页表 (Page Table)，比喻：查“分册”，找到第几页。 低 12 位 (11-0)：12 bit，页内偏移 (Offset)，比喻：在这一页中的具体行号。

关键硬件规则：

1. 页目录和页表都必须是 4KB 对齐的（地址末尾至少有 12 个 0）。
2. 每个目录/表有 1024 个条目（2的10次方），每个条目 4 字节，因此每个表正好占用 4KB。
3. 每个页表映射 4MB 内存（1024 页 × 4KB）。

### 2.2 我们的目标：恒等映射 (Identity Mapping)

开启分页最危险的时刻是：CPU 刚开启分页，但还没建立好映射，瞬间就会因为找不到指令的物理地址而崩溃（Triple Fault）。

最安全的做法：恒等映射。 即：虚拟地址 = 物理地址。例如：虚拟地址 0x10000 映射到物理地址 0x10000。这样开启分页后，我们之前的代码完全不需要修改，就能继续正常运行。我们将映射前 8MB 的内存（足够内核、位图和栈使用）。

## 🔬 三、 从汇编的角度看分页机制

在 C 语言里，分页机制看起来只是“设置几个结构体，然后改一下 CR0 和 CR3 寄存器”。但在汇编和硬件层面，分页机制的本质是：CPU 内部的 MMU（内存管理单元）劫持了所有的内存访问指令，并在指令真正执行前，强行插入了一次“地址翻译”过程。

### 3.1 三个掌控分页的“特权寄存器”

1. CR0 (Control Register 0) - 分页的“总开关” 第 31 位 (PG 位) 是分页启用位。 硬件视角：当 mov cr0, eax 执行完毕的下一个时钟周期，CPU 内部的数据通路就改变了。从此以后，所有带有 [] 的内存访问指令，都会被 MMU 拦截。
2. CR3 (Control Register 3) - 页目录的“物理指针” 作用是存储页目录 (Page Directory) 的物理基地址。 硬件视角：CR3 是 MMU 每次翻译地址时的起点。MMU 会直接读取 CR3 里的值，作为第一次内存读取的物理地址。
3. CR2 (Control Register 2) - 案发现场记录仪 作用是当分页出错（缺页异常）时，CPU 会自动把导致出错的那个虚拟地址存入 CR2。这是排查 Bug 的神器。

### 3.2 一条汇编指令的“奇幻漂流”

假设分页已经开启，你写了一行最普通的汇编代码：mov eax, [0x00010000]。在开启分页后，CPU 内部会发生以下精密动作：

步骤 1：MMU 拦截并拆解地址 CPU 发现 CR0 的 PG 位是 1，把 0x00010000 交给 MMU。MMU 将其按 10-10-12 规则强行拆成三段：高 10 位为 0（目录索引），中 10 位为 1（页表索引），低 12 位为 0（页内偏移）。

步骤 2：查“总目录” (Page Directory) MMU 读取 CR3（假设为 0x100000），计算目录项地址 0x100000 + (0 * 4) = 0x100000。MMU 发起一次真实的物理内存读取，读出 4 字节（页目录项 PDE）。假设读出 0x101003，其中高 20 位 0x10100 是页表的物理基地址。

步骤 3：查“分册” (Page Table) MMU 拿着页表基地址 0x10100，加上页表索引：0x10100 + (1 * 4) = 0x101004。MMU 发起第二次真实的物理内存读取，读出 4 字节（页表项 PTE）。假设读出 0x00020003，其中高 20 位 0x00020 是最终物理页的基地址。

步骤 4：拼接最终物理地址 MMU 把物理页基地址 0x00020 左移 12 位，变成 0x00020000，加上最初的页内偏移 0x000。最终物理地址 = 0x00020000。

步骤 5：执行真正的指令 MMU 把翻译好的物理地址交给 CPU 的总线接口单元。CPU 终于去物理内存 0x00020000 拿数据，放进 EAX。

顿悟时刻：你在汇编里写的一句 mov eax, [0x00010000]，在开启分页后，在底层实际上触发了 MMU 的两次额外物理内存读取（查目录、查表）！

### 3.3 页表项 (PTE/PDE) 的汇编位图

在汇编层面，页目录项和页表项根本没有“结构体”的概念，它们就是冷冰冰的 32 位整数：

31 到 22 位：物理页基地址 (20位) 21 到 12 位：保留/标志位 (AVL, G, PAT, D, A, PCD, PWT) 11 到 0 位：U/S, R/W, P (用户/内核, 读/写, 存在位)

P (Bit 0): Present。如果是 0，MMU 翻译时直接罢工，触发缺页异常（中断 14）。 R/W (Bit 1): Read/Write。0=只读，1=可写。 U/S (Bit 2): User/Supervisor。0=内核态(Ring 0)可访问，1=用户态(Ring 3)可访问。 物理页基地址 (Bit 12-31): 真正的物理内存地址（因为页是 4KB 对齐的，所以低 12 位永远是 0，被拿来当标志位用了）。

## 🏢 四、 怎么理解平坦内存模型？

理解了“平坦内存模型”，你就打通了从 16 位实模式到 32 位保护模式，再到现代操作系统的任督二脉。

核心定义：平坦内存模型（Flat Memory Model），就是把内存从“一个个带锁的隔断房”，砸墙打通成一个“从 0 到 4GB 的无敌大平层”。

### 4.1 回顾历史：没有平坦模型时有多痛苦？

在 16 位实模式下，内存是段式模型（Segmented）。因为 16 位寄存器最大只能表示 64KB，Intel 发明了“段基址 + 偏移量”的设计。

汇编示例： mov ax, 0x1000 mov ds, ax ; 设置数据段基址为 0x1000 mov bx, 0x0050 ; 偏移量为 0x0050 mov al, [bx] ; 实际访问的物理地址 = 0x1000 * 16 + 0x0050 = 0x10050

痛苦之处：一个段最大只能 64KB，数据大了就得频繁切换段寄存器；在 C 语言里，指针只是一个偏移量，你必须时刻记住它属于哪个段。

### 4.2 平坦模型是如何“骗”过 CPU 的？

进入 32 位保护模式后，寄存器变成了 32 位，理论上可以直接访问 4GB 内存了。但 x86 的硬件设计强制保留了分段机制（为了向后兼容）。

OS 开发者是怎么实现“平坦模型”的？ 答案是：把段基址设为 0，把段界限设为 4GB！

回想一下在 boot.asm 里写的 GDT（全局描述符表）： gdt_code: dw 0xFFFF ; 段界限 0-15 位 dw 0x0000 ; 基地址 0-15 位 <-- 基址是 0！ db 0x00 ; 基地址 16-23 位 <-- 基址是 0！ db 10011010b ; 访问权限 db 11001111b ; 标志：Granularity=1 (4KB粒度) -> 界限变成 4GB！ db 0x00 ; 基地址 24-31 位 <-- 基址是 0！

在保护模式下，CPU 访问内存的公式是：线性地址 = 段基址 + 偏移量。 因为所有段（代码段 CS、数据段 DS、栈段 SS）的基址都被我们强行设为了 0，界限都设为了 4GB。所以：偏移量 = 线性地址。所有的段在内存中完全重叠，覆盖整个 4GB 空间。这就是“平坦”的含义！

### 4.3 平坦模型与分页机制的完美衔接

这是操作系统内存管理的终极逻辑，请务必理清这三个地址的概念：

1. 逻辑地址 (Logical Address)：在 C 语言里写的指针（如 0x10000）。
2. 线性地址 (Linear Address)：经过分段机制 (GDT) 转换后的地址。公式：线性地址 = 段基址 + 逻辑地址。在平坦模型下：线性地址 = 逻辑地址！（分段机制被架空了，变成了透明通道）。
3. 物理地址 (Physical Address)：经过分页机制 (MMU) 转换后，真正打在内存条电容上的地址。公式：物理地址 = MMU翻译(线性地址)。

数据流向图解： [C 语言指针] 0x10000 │ ▼ (分段机制 GDT，因为基址为0，所以直接穿透) [线性地址] 0x10000 │ ▼ (分页机制 MMU，查页目录和页表) [物理地址] 0x10000 (假设做了恒等映射) │ ▼ [物理内存条] 翻转电容

为什么现代 OS 都要用平坦模型？ 因为分段机制太复杂、太容易出错。通过把段基址设为 0，OS 开发者在硬件强制要求分段的前提下，巧妙地“模拟”出了一个连续的 4GB 线性空间。然后，把内存管理的重担，全部交给了更强大、更灵活的分页机制 (Paging)。

## 🎯 五、 总结与展望

从汇编的角度看，分页机制根本不是魔法，而是硬件电路的重新布线：

1. CR3 是 MMU 的“导航起点”。
2. CR0.PG 是 MMU 的“电源开关”。
3. 每一次内存访问，MMU 都会在后台进行两次查表和一次拼接。
4. 页表项只是带有标志位的物理地址指针。

理解了这一层，你就彻底明白了为什么页目录和页表必须 4KB 对齐，也明白了为什么开启分页前必须做好恒等映射。

当你在终端看到 [Paging] Paging ENABLED! 时，你的 CPU 已经发生了质变。你不仅让内核“活”了过来，赋予了它管理物理内存的能力，现在更是为它戴上了 MMU 这副“眼镜”，让它拥有了现代操作系统的核心特征。

# 怎么从汇编的角度看分页机制

从汇编的角度看分页，核心就三件事：**控制寄存器怎么配、页表怎么建、地址翻译在指令层面如何体现**。下面以 x86-64 为主，兼顾 32 位保护模式，因为 32 位下分页的“存在感”更强，更容易看清机制。

---

## 一、分页相关的关键寄存器

|寄存器|作用|
|---|---|
|**CR0**|`PG` 位（bit 31）置 1 开启分页；`WP` 位控制写保护|
|**CR3**|存放**顶级页表物理基址**（x86-64 是 PML4，32 位是页目录）|
|**CR4**|`PAE`（物理地址扩展）、`PSE`（大页）、`PCIDE`（PCID）等|
|**CR2**|Page Fault 发生时，CPU 自动写入出错的**线性地址**|

汇编里操作它们只能用**特权指令**：

asm

mov cr3, rax      ; 加载页表基址（会刷新 TLB，除非用 PCID）
mov rax, cr0
or  rax, 1 << 31  ; 置 PG 位
mov cr0, rax      ; 开启分页

注意：`mov cr3, rax` 之后，CPU 立刻用新页表翻译后续指令取指。所以**这条指令本身及其后几条必须映射正确**，否则当场 triple fault。

---

## 二、从汇编看地址翻译：同一条指令，两种地址

汇编程序员写的是**线性地址（虚拟地址）**，但 CPU 访存用的是**物理地址**。分页在这中间插入了一层翻译。

看这条指令：

asm

mov rax, [0x400000]

- 汇编器/链接器认为它在访问线性地址 `0x400000`。
    
- CPU 实际执行时：
    
    1. 把 `0x400000` 拆成 `[PML4|PDPT|PD|PT|Offset]`。
        
    2. 从 CR3 出发逐级查表。
        
    3. 得到物理地址，比如 `0x1A0000`。
        
    4. 从物理地址 `0x1A0000` 读数据。
        

**从汇编源码完全看不出物理地址**。同一段代码，页表不同，访问的物理内存就不同。这就是虚拟化的本质。

---

## 三、页表项（PTE）的格式与汇编构造

x86-64 每级页表项都是 64 位，关键位：

|位|名称|含义|
|---|---|---|
|0|P|存在位|
|1|R/W|0=只读，1=可写|
|2|U/S|0=内核，1=用户可访问|
|3|PWT|写穿透|
|4|PCD|禁用缓存|
|5|A|已访问|
|6|D|已脏（仅末级）|
|7|PS|大页标志|
|12~51|物理地址|下一级表或页框的物理基址|
|63|NX|不可执行|

用汇编写页表，就是往内存里填这些 64 位值：

asm

; 假设 pml4 在 0x1000, pdpt 在 0x2000, pd 在 0x3000, pt 在 0x4000
; 建立映射：线性地址 0x0 -> 物理地址 0x0，2MB 大页，可读写
mov rax, 0x2000 | 0x3      ; PML4[0] = PDPT基址 | P|R/W
mov [0x1000], rax
mov rax, 0x3000 | 0x3      ; PDPT[0] = PD基址 | P|R/W
mov [0x2000], rax
mov rax, 0x0 | 0x83        ; PD[0] = 物理0 | P|R/W|PS(大页)
mov [0x3000], rax
mov rax, 0x1000            ; CR3 = PML4 物理基址
mov cr3, rax

这里 `0x83` = 二进制 `1000_0011`：P=1，R/W=1，PS=1（2MB 大页）。

---

## 四、Page Fault 在汇编层面的表现

当访问的页无效，CPU 会：

1. 把出错的线性地址写入 **CR2**。
    
2. 在栈上压入**错误码**（error code），格式：
    

text

bit 0: P    (0=页不存在, 1=权限违规)
bit 1: W/R  (0=读, 1=写)
bit 2: U/S  (0=内核态访问, 1=用户态访问)
bit 3: RSVD (保留位被置1)
bit 4: I/D  (1=取指时出错)

3. 跳转到 **IDT 第 14 号向量**对应的处理程序。
    

汇编里注册这个处理程序：

asm

; 假设 IDT 已建好，第14项指向 page_fault_handler
page_fault_handler:
    ; 此时栈顶是错误码，随后是 RIP/CS/RFLAGS/RSP/SS
    mov rax, cr2          ; 取回出错地址
    ; ... 判断原因，分配页，修页表 ...
    iretq                 ; 返回，重新执行出错指令

关键点：**`iretq` 返回后会重新执行那条出错的指令**。如果页表已修好，这次就能成功。

## 五、TLB 与汇编

TLB 是页表项的缓存，汇编程序员能做的控制有限：

asm

invlpg [0x400000]   ; 使该线性地址对应的 TLB 项失效
mov cr3, rax        ; 重载 CR3，刷新整个 TLB（非 PCID 时）

- 修改某个页表项后，必须 `invlpg` 或重载 CR3，否则 CPU 可能还用旧映射。
    
- 进程切换时，操作系统通常重载 CR3。若启用 PCID（CR4.PCIDE=1），CR3 低 12 位是 PCID，可避免全刷。

## 六、32 位保护模式下的分页（更直观）

32 位两级页表，CR3 指向**页目录（Page Directory）**：

text

线性地址 = [ 目录索引(10) | 表索引(10) | 偏移(12) ]

页目录项 / 页表项都是 32 位，格式类似。汇编构造：

asm

; 页目录在 0x1000，页表在 0x2000
; 映射线性 0x0 -> 物理 0x0，4KB 页
mov eax, 0x2000 | 0x3
mov [0x1000], eax        ; PDE[0]
mov eax, 0x0 | 0x3
mov [0x2000], eax        ; PTE[0]
mov eax, 0x1000
mov cr3, eax
mov eax, cr0
or  eax, 0x80000000
mov cr0, eax             ; 开启分页

开启分页的**瞬间**，CPU 开始用新页表翻译下一条指令。所以经典做法是：**把开启分页的代码和它后面的代码放在同一个已映射的页里**（恒等映射）。

## 七、汇编视角下的“分页看不到什么”

从汇编看分页，有几个重要事实：

1. **普通指令不区分虚拟/物理**。`mov`、`jmp`、`call` 全用线性地址，翻译是透明的。
    
2. **页表本身也是内存**。它放在物理内存里，但内核通常也把它映射到虚拟地址空间，方便读写。
    
3. **越权访问不会在汇编层面报错**，而是触发 Page Fault，由 OS 决定杀进程还是修页表。
    
4. **代码位置无关（PIC）与分页无关**。PIC 解决的是链接时地址不确定，分页解决的是运行时地址翻译，两者正交。
    
5. **大页减少 TLB 压力**。汇编里通过 PTE 的 PS 位置 1 来启用，翻译时少查一级。

怎么理解平坦内存模型

平坦内存模型（Flat Memory Model）是理解现代 x86 保护模式和长模式的关键。一句话概括：**所有段寄存器基址都为 0，段界限覆盖整个地址空间，逻辑地址直接等于线性地址，分段机制形同虚设，内存管理完全交给分页。**

下面从汇编视角把它讲透。

---

## 一、为什么会有“平坦”这个概念

在 8086 实模式下，内存是**分段**的：

text

物理地址 = 段基址 × 16 + 偏移

比如 `CS=0x1000, IP=0x0005`，物理地址 = `0x10000 + 0x0005 = 0x10005`。段基址是真实参与的，不同段指向不同物理区域，这就是**非平坦**的分段模型。

到了 386 保护模式，段寄存器不再存基址，而是存**选择子（Selector）**，指向 GDT 里的段描述符，描述符里才有 32 位基址和界限。地址翻译变成：

text

逻辑地址 = [ 段选择子 : 偏移 ]
              │
              ▼  查 GDT/LDT
线性地址 = 段基址 + 偏移
              │
              ▼  分页（可选）
物理地址

如果所有段的基址都设为 0，界限设为 4GB，那么：

text

线性地址 = 0 + 偏移 = 偏移

逻辑地址直接等于线性地址，段机制就“消失”了。这就是**平坦内存模型**。

---

## 二、平坦模型的具体配置

以 32 位保护模式为例，GDT 里通常定义几个段：

|选择子|段|基址|界限|权限|
|---|---|---|---|---|
|0x08|内核代码|0x00000000|0xFFFFF (4GB)|DPL=0, 可执行|
|0x10|内核数据|0x00000000|0xFFFFF|DPL=0, 可读写|
|0x18|用户代码|0x00000000|0xFFFFF|DPL=3, 可执行|
|0x20|用户数据|0x00000000|0xFFFFF|DPL=3, 可读写|

关键点：**基址全 0，界限全 4GB**。代码段和数据段只是权限不同，地址范围完全重叠。

段描述符的典型值：

asm

; 代码段描述符（基址0，界限4GB，可执行可读）
gdt_code:
    dw 0xFFFF        ; 界限低16位
    dw 0x0000        ; 基址低16位
    db 0x00          ; 基址中8位
    db 10011010b     ; P=1, DPL=0, S=1, Type=代码可执行可读
    db 11001111b     ; G=1(4KB粒度), D=1(32位), 界限高4位=0xF
    db 0x00          ; 基址高8位

`G=1` 时界限单位是 4KB，`0xFFFFF × 4KB = 4GB`。基址全 0，所以段内偏移就是线性地址。

## 三、汇编层面如何进入平坦模型

### 1. 从实模式切换到保护模式

asm

cli                     ; 关中断
lgdt [gdt_desc]         ; 加载 GDT
mov eax, cr0
or  eax, 1              ; 置 PE 位，开启保护模式
mov cr0, eax
jmp 0x08:flush          ; 远跳转，刷新 CS 为代码段选择子
flush:
    mov ax, 0x10        ; 数据段选择子
    mov ds, ax
    mov es, ax
    mov ss, ax
    mov fs, ax
    mov gs, ax
    ; 现在进入平坦模型：所有段基址=0，偏移=线性地址

远跳转 `jmp 0x08:flush` 是关键：它把 `CS` 换成选择子 `0x08`，同时刷新指令流水线。之后所有访存都用平坦模型。

### 2. 64 位长模式下的平坦

x86-64 长模式下，**分段基本被废除**：

- `CS/DS/ES/SS` 的基址强制为 0，忽略描述符里的基址。
    
- `FS/GS` 例外，基址仍有效，用于线程局部存储（TLS）。
    
- 地址翻译只剩分页。
    

所以长模式天然就是平坦模型，汇编里只需设置 `FS/GS` 基址（用 `wrmsr` 写 `IA32_FS_BASE` / `IA32_GS_BASE`）：

asm

; 设置 GS 基址为 0x1000
mov ecx, 0xC0000101     ; IA32_GS_BASE
mov eax, 0x1000
mov edx, 0
wrmsr

之后 `mov rax, gs:[0]` 访问的就是线性地址 `0x1000`。

## 四、平坦模型下，汇编程序员看到什么

### 1. 所有指针都是线性地址

asm

mov eax, [0x400000]     ; 直接访问线性地址 0x400000
jmp 0x401000            ; 直接跳到线性地址 0x401000
call func               ; func 的地址就是线性地址

没有“段:偏移”的概念，`ds:[0x400000]` 和 `[0x400000]` 等价，因为 `ds` 基址为 0。

### 2. 段寄存器仍然存在，但只是形式

- `CS` 决定权限（内核/用户）和位宽（32/64）。
    
- `SS` 必须与 `CS` 权限一致，否则异常。
    
- `DS/ES` 在长模式下几乎不用。
    
- `FS/GS` 用于 TLS。
    

### 3. 内存保护靠分页，不靠分段

在平坦模型下，段界限都是 4GB，段权限只在“内核/用户”层面区分。真正的精细保护（某页只读、某页不可执行、某页不存在）全部由**页表项**控制。

; 改页表项，清 R/W 位，而不是改段描述符

## 五、平坦模型与分页的关系

两者是**正交**的，但现代系统把它们组合使用：

text

逻辑地址 --[平坦分段: 基址0]--> 线性地址 --[分页]--> 物理地址

- **平坦分段**：让逻辑地址 = 线性地址，简化编程模型。
    
- **分页**：提供隔离、虚拟化、按需分配、保护。
    

如果没有分页，平坦模型下所有进程共享同一个 4GB 线性空间，毫无隔离。所以**平坦模型必须配合分页才有实用价值**。

## 六、平坦模型 vs 非平坦模型

|维度|非平坦（实模式/多段）|平坦模型|
|---|---|---|
|段基址|非 0，各段不同|全 0|
|逻辑地址|段:偏移，物理=段×16+偏移|等于线性地址|
|指针|远指针（段:偏移）|近指针（单一地址）|
|保护|段界限+权限|主要靠分页|
|编程复杂度|高，需管理段|低，像平坦数组|
|典型场景|8086、早期 DOS|现代 OS（Linux/Windows）|

## 七、为什么现代系统选择平坦模型

1. **编程简单**：C 指针就是线性地址，不需要 far/near 区分。
    
2. **编译器友好**：不需要为每个段生成不同的寻址代码。
    
3. **与分页配合好**：分页提供更细粒度的保护，分段显得多余。
    
4. **64 位硬件强制**：长模式下分段被弱化，平坦是唯一选择。
    
5. **移植性好**：与 RISC 架构（本身无分段）的模型一致。

## 二、GDT 描述符格式详解

每个段描述符 8 字节，64 位，布局如下（低地址到高地址）：

text

 63        56 55   52 51    48 47        40 39    32
+------------+-------+--------+------------+---------+
|  base_hi   | flags | lim_hi |  access    | base_mid|
+------------+-------+--------+------------+---------+
 31                    16 15                    0
+------------------------+-----------------------+
|       base_low         |      limit_low        |
+------------------------+-----------------------+

字段含义：

|字段|位|说明|
|---|---|---|
|limit_low|15:0|段界限低 16 位|
|base_low|31:16|段基址低 16 位|
|base_mid|39:32|段基址 23:16|
|access|47:40|访问权限字节|
|flags + lim_hi|55:48|高 4 位标志 + 界限 19:16|
|base_hi|63:56|段基址 31:24|

**访问字节（access）** 位定义：

text

bit 7: P   存在位，必须为 1
bit 6-5: DPL  特权级 00=内核, 11=用户
bit 4: S   1=代码/数据段, 0=系统段
bit 3: E   1=代码段, 0=数据段
bit 2: DC  代码: 1=一致段; 数据: 1=向下扩展
bit 1: RW  代码: 1=可读; 数据: 1=可写
bit 0: A   已访问位，CPU 自动置 1

**标志字节高 4 位（flags）**：

text

bit 3: G   粒度，0=1字节, 1=4KB
bit 2: D/B 0=16位, 1=32位（代码段=默认操作数宽度，数据段=栈指针宽度）
bit 1: L   1=64位代码段（长模式），32位下必须为 0
bit 0: AVL 操作系统可用

本例中代码段 access = `10011010b`：

- P=1，DPL=00，S=1，E=1，DC=0，RW=1，A=0
    

数据段 access = `10010010b`：

- P=1，DPL=00，S=1，E=0，DC=0，RW=1，A=0
    

flags = `11001111b`：

- G=1（4KB 粒度），D/B=1（32位），L=0，AVL=0，界限高 4 位=0xF
    

**界限计算**：`0xFFFFF × 4KB = 4GB`，所以覆盖整个 32 位地址空间。  
**基址**：全部为 0。

两者结合，就是**平坦模型**。

## 三、关键步骤解析

### 1. `cli` 关中断

切换过程中 IDT 还没建立，一旦中断会跳转到未定义的处理程序，导致崩溃。所以必须先关中断。

### 2. `lgdt [gdt_desc]`

把 GDT 的基址和界限载入 GDTR 寄存器。`gdt_desc` 是 6 字节结构：

text

+----------------+----------------+
|  界限 (2字节)   |  基址 (4字节)   |
+----------------+----------------+

在实模式下，基址就是物理地址，因为还没开启分页。

### 3. 置 [CR0.PE](https://cr0.pe/)

asm

mov eax, cr0
or  eax, 1
mov cr0, eax

这条指令执行后，CPU 进入保护模式。但**此时 CS 还是实模式的值**，必须立刻远跳转刷新。

### 4. `jmp 0x08:pm_entry`

远跳转同时做两件事：

- 把 `CS` 换成选择子 `0x08`（指向代码段描述符）。
    
- 跳转到 `pm_entry` 的线性地址。
    

选择子格式：

text

15                3  2   1  0
+-----------------+----+-----+
|   索引 (13位)    | TI | RPL |
+-----------------+----+-----+

- `0x08` = 索引 1，TI=0（GDT），RPL=00（内核）。
    
- 索引 1 正好是 GDT 里的 `gdt_code`（索引 0 是空描述符）。
    

### 5. 初始化数据段

asm

mov ax, 0x10
mov ds, ax
mov es, ax
mov ss, ax
mov fs, ax
mov gs, ax

`0x10` = 索引 2，指向 `gdt_data`。现在所有数据段都是基址 0、界限 4GB，进入平坦模型。

### 6. 写显存

asm

mov edi, 0xB8000
mov [edi], al
mov [edi+1], ah

在平坦模型下，`0xB8000` 就是线性地址，等于物理地址（未开启分页时）。直接写显存，屏幕上出现文字。

## 五、常见陷阱

1. **忘记远跳转**：置 PE 后不刷新 CS，CPU 行为未定义，通常直接崩溃。
    
2. **GDT 界限算错**：`lgdt` 的界限是 `大小 - 1`，不是大小。
    
3. **栈指针没设**：进入保护模式后 `ss` 变了，`esp` 必须重设，否则栈指向错误位置。
    
4. **中断没关**：切换期间中断会跳转到无效 IDT。
    
5. **描述符对齐**：GDT 最好 8 字节对齐，虽然不强制，但性能更好。
    
6. **引导扇区签名**：最后两字节必须是 `0xAA55`，否则 BIOS 不认。
    
7. **BITS 切换**：`BITS 16` 和 `BITS 32` 必须正确标注，否则 NASM 生成错误编码。
    

---

## 六、如果要用 C 内核继续

切换到平坦保护模式后，可以跳转到 C 内核：

asm

extern kernel_main
jmp 0x08:kernel_entry
kernel_entry:
    mov ax, 0x10
    mov ds, ax
    ; ...
    call kernel_main
    hlt

C 代码里所有指针都是线性地址，编译时用 `-m32 -ffreestanding`，链接脚本指定基址（如 `0x100000`）。这就是 Linux 早期启动流程的简化版。

> **切换到平坦保护模式的核心是：建 GDT（基址 0、界限 4GB）→ `lgdt` → 置 [CR0.PE](https://cr0.pe/) → 远跳转刷新 CS → 初始化数据段。之后逻辑地址直接等于线性地址，分段退化为权限标记，内存管理交给分页。**

# 分页（Paging）是操作系统和 CPU 联手实现的**内存管理机制**：把虚拟地址空间和物理内存都切成固定大小的"页"，按需建立映射关系。它是现代操作系统的地基之一。结合我们之前聊的虚拟内存，可以这样理解：

## 1. 要解决的问题

没有分页时，程序必须整段装进物理内存的**连续**区域，带来三个致命伤：

- **内存碎片**：程序进进出出，物理内存被切成碎片，剩下总空间够却装不下任何程序；
    
- **无法隔离**：进程 A 可以随意读写进程 B 的内存；
    
- **程序太大**：程序比物理内存还大就跑不了。
    

## 2. 核心思想：切豆腐块 + 查表翻译

**页（Page）**：虚拟地址空间切成固定大小的块，x86-64 上通常 **4KB**（也可用 2MB/1GB 大页）。 **页帧（Page Frame）**：物理内存切成同样大小的块。 **页表（Page Table）**：一张映射表，记录"虚拟页 N → 物理页帧 M"。

CPU 每次访存时，**MMU（内存管理单元）** 硬件自动做翻译：

plain

```plain
虚拟地址 = [  页号 (高 48 位中的若干位)  |  页内偏移 (低 12 位)  ]
                ↓ 查页表                     ↓ 原样保留
物理地址 = [  页帧号 (从页表查到)         |  页内偏移          ]
```

关键洞察：**偏移部分不经过翻译，只有页号需要换**。就像快递地址：只要查到"哪栋楼"（页号），楼内"哪一户"（偏移）照抄即可。

## 3. 多级页表：空间换时间的艺术

朴素方案是一张大表：48 位地址空间 ÷ 4KB 页 = 2³⁶ 个条目，每条 8 字节 = **256GB 的页表**，不可接受。

x86-64 用 **4 级页表**（Linux 通常 4 级：PGD → PUD → PMD → PTE），把页号再拆成 4 段：

plain

```plain
虚拟地址: [ PML4 9位 | PDPT 9位 | PD 9位 | PT 9位 | 偏移 12位 ]  (共 48 位)
              ↓         ↓         ↓         ↓
           一级表 → 二级表 → 三级表 → 四级表 → 页帧号
```

每一级只有 512 个条目（9 位），按需创建——**用不到的地址空间根本不存在对应的页表**，一张页表通常只占几 KB~几 MB。代价是 4 次内存查询（硬件用 **TLB** 缓存翻译结果来补偿）。

## 4. 页表条目不只是一个地址

每个 PTE（页表项）虽然 64 位，但**真正存物理地址的只有中间 40 位左右**，其余位是权限和状态标志：

plain

```plain
┌────────────────────────┬──┬──┬──┬──┬──┬──┬──┐
│  物理页帧号 (40+位)      │AVL│D │A │PCD│PWT│U/S│R/W│P│
└────────────────────────┴──┴──┴──┴──┴──┴──┴──┘
 P    = Present   该页是否在物理内存（不在则触发缺页中断）
 R/W  = 只读/可写
 U/S  = 用户态/内核态（用户进程不能访问内核页 → 这就是进程隔离的硬件实现）
 A    = Accessed  最近是否被访问（供 LRU 换页用）
 D    = Dirty     是否被写过（决定换出时要不要写回磁盘）
```

之前聊汇编时的**段错误（Segmentation Fault）**就是这么来的：CPU 发现你要访问的页 U/S=0 或 R/W=0，硬件直接抛异常，OS 杀掉进程。所以"段错误"其实是**页错误的一种**（历史上来自更早的分段机制，名字沿用了）。

## 5. 缺页中断与换页：内存不够时发生什么

- **缺页（Page Fault）**：访问的页 P=0，CPU 陷入内核，OS 处理：
    
    - 页在磁盘交换区（swap）→ 找一个空闲页帧（没有就按 LRU 踢出一个），从磁盘读入，更新页表，重新执行指令（对程序完全透明）；
        
    - 访问了未映射的地址 → 发 SIGSEGV，你收到段错误。
        
- 这就回答了"为什么内存满了电脑卡"：频繁的磁盘换页（**抖动 thrashing**）让磁盘访问伪装成内存访问，速度差了一万倍。
    

## 6. 从汇编视角看它（呼应之前）

写汇编时你已经在无意识用分页：

- 你用的地址全是**虚拟地址**——`mov (%rax), %rbx` 里的 rax 只有经过 MMU 翻译才碰到真实物理内存；
    
- **平坦内存模型**：现代 OS 给每个进程一张页表，所有段基址设为 0，"分段"名存实亡，分页独挑大梁；
    
- 内核态/用户态切换（syscall）时，OS 会换页表基址寄存器（`CR3`），同一虚拟地址瞬间映射到不同物理页——**同一个地址，两个世界**。
    

## 心智模型总结

> 分页 = **地址翻译 + 按需映射 + 权限检查**，由 MMU 硬件查多级页表完成。 页号查表换页帧，偏移原样保留； 权限位（P/R-W/U-S）由硬件强制，构成进程隔离； 不在内存的页触发缺页中断，OS 从磁盘取或杀掉进程。

想亲手验证的话，Linux 下有几个直观入口：`/proc/self/maps` 看你的进程虚拟地址空间布局；`getconf PAGE_SIZE` 看页大小；`mincore()` 系统调用可查某段内存是否驻留在物理内存。需要我写个小程序演示"申请 1GB 内存却不占物理内存"（mmap 的按需分配），你会看到分页机制的实时效果。

## 1. 总纲：普通指令无感知，特殊指令全透明

从你之前学的汇编看，分页是**默认背景**：

asm

```asm
mov  (%rax), %rbx     # rax 是虚拟地址；MMU 翻译后才碰到物理内存
```

CPU 文档把这叫 **平坦内存模型（Flat Model）**——分段机制名存实亡（所有段基址=0），分页接管一切。99% 的汇编代码不需要关心分页，直到你碰下面这些东西。

## 2. 与分页直接相关的寄存器和指令（x86-64）

Table

|寄存器/指令|作用|权限|
|:--|:--|:--|
|`CR0.PG`|分页总开关（bit 31），置 1 才启用分页|内核|
|`CR3`|当前页表基址（指向 PML4），**换页表就是换进程**|内核|
|`CR4.PAE / LA57`|启用物理地址扩展 / 5 级页表|内核|
|`EFER.LME`|长模式（64 位）开关，配合分页才有 64 位地址空间|内核|
|`mov %rax, %cr3`|切换地址空间，**下一条指令起就用新页表翻译**|内核|
|`invlpg (%rax)`|踢掉 TLB 中某地址的缓存条目（改页表后必须做）|内核|
|`#PF`（中断 14）|缺页/权限错误，CPU 自动陷入|硬件触发|

这就是汇编角度的分页本质：**分页 = CR3 指向的一堆表 + MMU 每次访存查表**。

## 3. 上下文切换时汇编在干什么（核心场景）

OS 调度进程时，汇编层的关键三步：

asm

```asm
# 保存旧进程上下文后...
mov  新进程的页表基址, %rax
mov  %rax, %cr3        # ← 换页表！从此同一虚拟地址映射到不同物理页
jmp  新进程恢复点
```

这就是"**同一地址，两个世界**"：代码段里 `0x400000` 这个虚拟地址，进程 A 里映射到物理帧 X，进程 B 里映射到物理帧 Y。页表一换，世界就换了。用户态程序完全无感，因为切换发生在内核里。

引申：**KAISER/KPTI**（内核页表隔离）补丁之后，syscall 进出内核还会**多换一次 CR3**——把内核页表从用户页表里拆出去，防 Meltdown 漏洞。代价就是 syscall 变贵，这是"汇编指令 + 分页"相互作用的真实代价。

## 4. 页错误处理：汇编能看到的最直接交互

用户态执行 `mov (%rax), %rbx` 时，如果 MMU 发现该页 P=0 或权限不符，CPU 做一件**非常汇编的事情**：

1. 压入错误码（哪类错：不存在/只读/用户态访问内核页）；
    
2. 通过 **IDT 第 14 号门** 跳入内核的页错误处理程序（ring 3 → ring 0，**CPU 硬件自动切换到内核栈**，压入 SS/RSP/RFLAGS/CS/RIP——就是中断帧）；
    
3. 内核处理完，用 `iretq` 返回，**重新执行那条触发故障的指令**（fault 类异常是可恢复的）。
    

手写页错误 handler 是汇编学习者的经典练习，你会亲眼看到：一个普通 `mov` 如何触发一次完整的特权级切换。

## 5. 用汇编思维"手算"一次地址翻译

给你 CR3 和一个虚拟地址，四级页表的走查可以直接写成循环：

asm

```asm
# %rdi = 虚拟地址, %cr3 = PML4 基址
walk:
    mov  %cr3, %rax          # L4 表基址（物理地址！）
    mov  %rdi, %rbx
    shr  $39, %rbx
    and  $0x1ff, %rbx        # 取 PML4 索引（位 47-39）
    mov  (%rax,%rbx,8), %rax # 读 L4 项 → 下一级表基址（低 12 位是标志位）
    and  $~0xfff, %rax       # 清掉标志位

    mov  %rdi, %rbx
    shr  $30, %rbx
    and  $0x1ff, %rbx        # PDPT 索引
    mov  (%rax,%rbx,8), %rax
    and  $~0xfff, %rax
    # ... 同理走 PD、PT，最后拼上低 12 位页内偏移
```

要点全在这条循环里：

- 每级索引 = 地址中 9 位 → `shr + and` 提取；
    
- 表项是**物理地址**（用户态永远看不到，只有 MMU 和内核能摸）；
    
- 低 12 位是标志位，必须 `and $~0xfff` 清掉再当指针用；
    
- 这正是 MMU 硬件每个访存周期做的事情，只是它是全硬件流水线。
    

## 6. 回到实验：`mincore` 结果怎么读

plain

```plain
前 8 页驻留位图: 10000000
```

- mmap 512MB 只是**在页表里"画了个大饼"**——分配了虚拟页号范围，P 位全 0，物理页帧一个没给（RSS 才 916KB）；
    
- 写 `p[0]` 触发 #PF → 内核分配 1 个物理帧、填 PTE、iretq 重执行 → 位图第 0 位置 1；
    
- 逐页 touch 后 RSS 涨到 512MB——**物理内存按 4KB 的粒度，按需付账**。
    

这就是分页机制在汇编/系统层的完整闭环：`mov` 触发 #PF → IDT 14 号门进内核 → 内核分配页帧改页表 → 返回重执行，全程对程序透明。
