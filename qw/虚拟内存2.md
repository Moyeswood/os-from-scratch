## 💻 二、 虚拟内存分页机制 (Paging)

### 2.1 核心概念：什么是分页机制？

在开启分页之前，我们的 C 语言指针直接等于物理地址。这非常危险，一个写错的指针就能覆盖内核代码或硬件寄存器。

**分页机制的本质**：在 CPU 和物理内存之间加了一层“翻译官”（MMU）。CPU 发出的不再是物理地址，而是“虚拟地址”，MMU 负责将其翻译成真实的物理地址。

**通俗比喻：图书馆的索引系统** 想象物理内存是一个巨大的图书馆，里面有 4GB 的书（物理地址）。

- **没有分页时**：你直接走到书架前找书（直接访问物理地址）。
- **有分页时**：你不能直接去书架。你必须先查**总目录（Page Directory）**，目录告诉你去哪个**分册（Page Table）**，分册再告诉你具体的**书架位置（Page）**。

**x86 分页的三级结构** 在 32 位 x86 系统中，32 位的虚拟地址被 MMU 强行拆分成三部分：

- **高 10 位 (31-22)**：10 bit，索引 **页目录 (Page Directory)**。比喻：查“总目录”，找到第几本分册。
- **中 10 位 (21-12)**：10 bit，索引 **页表 (Page Table)**。比喻：查“分册”，找到第几页。
- **低 12 位 (11-0)**：12 bit，**页内偏移 (Offset)**。比喻：在这一页中的具体行号。

**关键硬件规则**：

1. **页目录**和**页表**都必须是 **4KB 对齐**的（地址末尾至少有 12 个 0）。
2. 每个目录/表有 **1024 个条目**（2的10次方），每个条目 4 字节，因此每个表正好占用 4KB。
3. 每个页表映射 4MB 内存（1024 页 × 4KB）。

### 2.2 我们的目标：恒等映射 (Identity Mapping)

开启分页最危险的时刻是：CPU 刚开启分页，但还没建立好映射，瞬间就会因为找不到指令的物理地址而崩溃（Triple Fault）。

**最安全的做法：恒等映射。** 即：**虚拟地址 = 物理地址**。例如：虚拟地址 `0x10000` 映射到物理地址 `0x10000`。这样开启分页后，我们之前的代码完全不需要修改，就能继续正常运行。我们将映射前 **8MB** 的内存（足够内核、位图和栈使用）。

### 2.3 完整代码实现（含逐行详细注释）

以下是 `kernel/paging.h` 文件的完整内容：


#ifndef PAGING_H             // 防止头文件被重复包含
#define PAGING_H

#include "types.h"           // 引入基础类型定义（如 uint32_t）

// 页表项和页目录项的标志位
#define PAGE_PRESENT  0x01   // 标志位：页在内存中 (Present)
#define PAGE_WRITE    0x02   // 标志位：页可写 (Read/Write)
#define PAGE_USER     0x04   // 标志位：用户态可访问 (User/Supervisor)

// 页表结构 (1024 个条目，每个 4 字节，共 4KB)
// 用于映射 4MB 的物理内存
typedef struct {
    uint32_t entries[1024];  // 1024 个页表项，每个项 32 位
} page_table_t;

// 页目录结构 (1024 个条目，每个 4 字节，共 4KB)
// 用于指向 1024 个页表，总共映射 4GB 内存
typedef struct {
    uint32_t entries[1024];  // 1024 个页目录项，每个项 32 位
} page_directory_t;

// 初始化分页机制的函数声明
void paging_init();

#endif


以下是 `kernel/paging.c` 文件的完整内容：

#include "paging.h"          // 引入分页头文件
#include "serial.h"          // 引入串口驱动（用于打印调试日志）

// 【关键】：必须 4KB 对齐！这是 x86 硬件的强制要求。
// 因为页表项的低 12 位被用作标志位，如果地址不 4KB 对齐，物理地址就会出错。
// 我们定义 1 个页目录和 2 个页表（映射 8MB 内存）
__attribute__((aligned(4096))) page_directory_t kernel_page_directory;
__attribute__((aligned(4096))) page_table_t kernel_page_tables[2];

void paging_init() {
    // 打印初始化开始日志
    serial_puts("\n\r[Paging] Initializing paging mechanism...\n\r"); 

    // 1. 清空页目录和页表（全部置 0，表示页不在内存中）
    for (int i = 0; i < 1024; i++) {
        kernel_page_directory.entries[i] = 0; // 清空页目录的 1024 个条目
    }
    for (int i = 0; i < 2048; i++) {
        // 2 个页表，共 2048 个条目，全部清零
        kernel_page_tables[0].entries[i] = 0;
        kernel_page_tables[1].entries[i] = 0;
    }

    // 2. 设置页目录项 (PDE)，指向页表
    // 物理地址 | 标志位 (Present + Write)
    // kernel_page_tables[0] 映射前 4MB，kernel_page_tables[1] 映射后 4MB
    kernel_page_directory.entries[0] = ((uint32_t)&kernel_page_tables[0]) | PAGE_PRESENT | PAGE_WRITE;
    kernel_page_directory.entries[1] = ((uint32_t)&kernel_page_tables[1]) | PAGE_PRESENT | PAGE_WRITE;

    // 3. 设置页表项 (PTE)，建立恒等映射 (虚拟地址 = 物理地址)
    // 映射前 8MB (2048 个页，每个页 4KB)
    for (int i = 0; i < 2048; i++) {
        uint32_t physical_addr = i * 4096; // 计算第 i 页的物理起始地址
        int table_idx = i / 1024;          // 计算属于哪个页表 (0 或 1)
        int entry_idx = i % 1024;          // 计算在页表中的第几个条目
        
        // 将物理地址与标志位 (Present + Write) 组合，写入页表项
        kernel_page_tables[table_idx].entries[entry_idx] = physical_addr | PAGE_PRESENT | PAGE_WRITE;
    }

    // 打印页表建立完成日志
    serial_puts("[Paging] Page tables set up (Identity mapping 8MB).\n\r"); 

    // 4. 加载页目录到 CR3 寄存器
    // CR3 存储页目录的物理地址，这是 MMU 查表的起点
    __asm__ volatile("mov %0, %%cr3" : : "r"(&kernel_page_directory));
    // 打印 CR3 加载完成日志
    serial_puts("[Paging] CR3 loaded.\n\r"); 

    // 5. 开启分页机制
    // 设置 CR0 寄存器的第 31 位 (PG 位) 为 1
    uint32_t cr0;
    __asm__ volatile("mov %%cr0, %0" : "=r"(cr0)); // 读取 CR0 到 cr0 变量
    cr0 |= 0x80000000;                             // 将第 31 位 (PG) 置为 1
    __asm__ volatile("mov %0, %%cr0" : : "r"(cr0)); // 将修改后的值写回 CR0
    
    // 打印分页开启成功日志
    serial_puts("[Paging] Paging ENABLED! (CR0.PG = 1)\n\r"); 
}

## 🔬 三、 从汇编的角度看分页机制

在 C 语言里，分页机制看起来只是“设置几个结构体，然后改一下 CR0 和 CR3 寄存器”。但在汇编和硬件层面，分页机制的本质是：**CPU 内部的 MMU（内存管理单元）劫持了所有的内存访问指令，并在指令真正执行前，强行插入了一次“地址翻译”过程。**

### 3.1 三个掌控分页的“特权寄存器”

在 x86 汇编中，有三个控制寄存器（Control Registers）是分页机制的绝对核心。它们不能用普通的 `mov` 在内存间传递，只能和通用寄存器（如 EAX）交互。

1. **CR0 (Control Register 0) - 分页的“总开关”**
    - **第 31 位 (PG 位)**：分页启用位。
    - **硬件视角**：当 `mov cr0, eax` 执行完毕的下一个时钟周期，CPU 内部的数据通路就改变了。从此以后，所有带有 `[]` 的内存访问指令，都会被 MMU 拦截。
2. **CR3 (Control Register 3) - 页目录的“物理指针”**
    - **作用**：存储**页目录 (Page Directory)** 的物理基地址。
    - **硬件视角**：CR3 是 MMU 每次翻译地址时的**起点**。MMU 会直接读取 CR3 里的值，作为第一次内存读取的物理地址。
3. **CR2 (Control Register 2) - 案发现场记录仪**
    - **作用**：当分页出错（缺页异常）时，CPU 会自动把**导致出错的那个虚拟地址**存入 CR2。这是排查 Bug 的神器。

### 3.2 一条汇编指令的“奇幻漂流”

假设分页已经开启，你写了一行最普通的汇编代码：`mov eax, [0x00010000]`。在开启分页后，CPU 内部会发生以下精密动作：

**步骤 1：MMU 拦截并拆解地址** CPU 发现 CR0 的 PG 位是 1，把 `0x00010000` 交给 MMU。MMU 将其按 **10-10-12** 规则强行拆成三段：高 10 位为 `0`（目录索引），中 10 位为 `1`（页表索引），低 12 位为 `0`（页内偏移）。

**步骤 2：查“总目录” (Page Directory)** MMU 读取 CR3（假设为 `0x100000`），计算目录项地址 `0x100000 + (0 * 4) = 0x100000`。MMU 发起一次真实的物理内存读取，读出 4 字节（页目录项 PDE）。假设读出 `0x101003`，其中高 20 位 `0x10100` 是页表的物理基地址。

**步骤 3：查“分册” (Page Table)** MMU 拿着页表基地址 `0x10100`，加上页表索引：`0x10100 + (1 * 4) = 0x101004`。MMU 发起第二次真实的物理内存读取，读出 4 字节（页表项 PTE）。假设读出 `0x00020003`，其中高 20 位 `0x00020` 是最终物理页的基地址。

**步骤 4：拼接最终物理地址** MMU 把物理页基地址 `0x00020` 左移 12 位，变成 `0x00020000`，加上最初的页内偏移 `0x000`。最终物理地址 = `0x00020000`。

**步骤 5：执行真正的指令** MMU 把翻译好的物理地址交给 CPU 的总线接口单元。CPU 终于去物理内存 `0x00020000` 拿数据，放进 EAX。

** 顿悟时刻**：你在汇编里写的一句 `mov eax, [0x00010000]`，在开启分页后，**在底层实际上触发了 MMU 的两次额外物理内存读取（查目录、查表）**！

### 3.3 页表项 (PTE/PDE) 的汇编位图

在汇编层面，页目录项和页表项根本没有“结构体”的概念，它们就是冷冰冰的 32 位整数：

text

 31  22 21  12 11  9 8 7 6 5 4 3 2 1 0
[ 物理页基地址 (20位) ] [ AVL ] G PAT D A PCD PWT U/S R/W P

- **P (Bit 0)**: Present。如果是 0，MMU 翻译时直接罢工，触发缺页异常（中断 14）。
- **R/W (Bit 1)**: Read/Write。0=只读，1=可写。
- **U/S (Bit 2)**: User/Supervisor。0=内核态(Ring 0)可访问，1=用户态(Ring 3)可访问。
- **物理页基地址 (Bit 12-31)**: 真正的物理内存地址（因为页是 4KB 对齐的，所以低 12 位永远是 0，被拿来当标志位用了）。

### 3.4 当分页出错时（缺页异常 Page Fault）

如果你访问了一个没有设置 `Present` 位的虚拟地址，或者试图往只读页写数据，MMU 会立刻阻止这次访问，并触发 **中断 14 (Page Fault)**。

在汇编层面，CPU 会自动做以下几件事：

1. **停止当前指令**：那条导致出错的汇编指令**完全没有执行**，就像没发生过一样。
2. **压栈错误码 (Error Code)**：CPU 会自动把一个 32 位的错误码压入内核栈。这个错误码告诉 OS 是哪种违规（比如 Bit 0=0 表示页不存在，Bit 1=1 表示写操作违规）。
3. **记录案发现场**：CPU 把导致出错的那个**虚拟地址**，自动存入 **CR2** 寄存器。
4. **跳转中断处理程序**：CPU 去 IDT 的第 14 号条目，跳转到你写的 `page_fault_handler`。

## 四、 怎么理解平坦内存模型？

理解了“平坦内存模型”，你就打通了从 16 位实模式到 32 位保护模式，再到现代操作系统的任督二脉。

**核心定义**：平坦内存模型（Flat Memory Model），就是把内存从“一个个带锁的隔断房”，砸墙打通成一个“从 0 到 4GB 的无敌大平层”。

### 4.1 回顾历史：没有平坦模型时有多痛苦？

在 16 位实模式下，内存是**段式模型（Segmented）**。因为 16 位寄存器最大只能表示 64KB，Intel 发明了“段基址 + 偏移量”的设计。

汇编示例：

nasm

mov ax, 0x1000
mov ds, ax          ; 设置数据段基址为 0x1000
mov bx, 0x0050      ; 偏移量为 0x0050
mov al, [bx]        ; 实际访问的物理地址 = 0x1000 * 16 + 0x0050 = 0x10050

**痛苦之处**：一个段最大只能 64KB，数据大了就得频繁切换段寄存器；在 C 语言里，指针只是一个偏移量，你必须时刻记住它属于哪个段。

### 4.2 平坦模型是如何“骗”过 CPU 的？

进入 32 位保护模式后，寄存器变成了 32 位，理论上可以直接访问 4GB 内存了。但 x86 的硬件设计**强制保留了分段机制**（为了向后兼容）。

**OS 开发者是怎么实现“平坦模型”的？** 答案是：**把段基址设为 0，把段界限设为 4GB！**

回想一下在 `boot.asm` 里写的 GDT（全局描述符表）：

nasm

gdt_code:
    dw 0xFFFF       ; 段界限 0-15 位
    dw 0x0000       ; 基地址 0-15 位  <-- 基址是 0！
    db 0x00         ; 基地址 16-23 位 <-- 基址是 0！
    db 10011010b    ; 访问权限
    db 11001111b    ; 标志：Granularity=1 (4KB粒度) -> 界限变成 4GB！
    db 0x00         ; 基地址 24-31 位 <-- 基址是 0！

在保护模式下，CPU 访问内存的公式是：**线性地址 = 段基址 + 偏移量**。 因为所有段（代码段 CS、数据段 DS、栈段 SS）的基址都被我们强行设为了 0，界限都设为了 4GB。所以：**偏移量 = 线性地址**。所有的段在内存中**完全重叠**，覆盖整个 4GB 空间。这就是“平坦”的含义！

### 4.3 平坦模型与分页机制的完美衔接

这是操作系统内存管理的终极逻辑，请务必理清这三个地址的概念：

1. **逻辑地址 (Logical Address)**：在 C 语言里写的指针（如 `0x10000`）。
2. **线性地址 (Linear Address)**：经过**分段机制 (GDT)** 转换后的地址。公式：`线性地址 = 段基址 + 逻辑地址`。**在平坦模型下：线性地址 = 逻辑地址！**（分段机制被架空了，变成了透明通道）。
3. **物理地址 (Physical Address)**：经过**分页机制 (MMU)** 转换后，真正打在内存条电容上的地址。公式：`物理地址 = MMU翻译(线性地址)`。

**数据流向图解**：

[C 语言指针] 0x10000 
      │
      ▼ (分段机制 GDT，因为基址为0，所以直接穿透)
[线性地址] 0x10000 
      │
      ▼ (分页机制 MMU，查页目录和页表)
[物理地址] 0x10000 (假设做了恒等映射)
      │
      ▼
[物理内存条] 翻转电容

**为什么现代 OS 都要用平坦模型？** 因为分段机制太复杂、太容易出错。通过把段基址设为 0，OS 开发者**在硬件强制要求分段的前提下，巧妙地“模拟”出了一个连续的 4GB 线性空间**。然后，把内存管理的重担，全部交给了更强大、更灵活的**分页机制 (Paging)**。

## 🎯 五、 总结与展望

从汇编的角度看，分页机制根本不是魔法，而是**硬件电路的重新布线**：

1. **CR3** 是 MMU 的“导航起点”。
2. **CR0.PG** 是 MMU 的“电源开关”。
3. 每一次内存访问，MMU 都会在后台进行**两次查表**和**一次拼接**。
4. 页表项只是**带有标志位的物理地址指针**。

理解了这一层，你就彻底明白了为什么页目录和页表必须 **4KB 对齐**，也明白了为什么开启分页前必须做好**恒等映射**。

当你在终端看到 `[Paging] Paging ENABLED!` 时，你的 CPU 已经发生了质变。你不仅让内核“活”了过来，赋予了它管理物理内存的能力，现在更是为它戴上了 MMU 这副“眼镜”，让它拥有了现代操作系统的核心特征。

接下来，我们将基于这个稳固的内存基础，开始构建**命令行 Shell**，让你的操作系统真正与人类产生交互！
